# Agent测评出题

检验助手能否完成真实用户需求，不把题目写成工具教程，也不因助手尚未支持而避开合理需求。本Skill不授权付费测评、产品修改或部署；付费测量的约定见"判定与交付"。

## 范围与独立性

- 沿用用户指定应用、范围和题数；未指定数量时按覆盖范围建议。题集按 [题集的统一格式](references/question-format.md) 编写（`cases.json`、`questions.json`、`runs.json`、`seal.json`、`.blind`）；存放位置与登记方式由查看器的运行环境约定，本Skill不作目录要求。区分开发回归、新题对照、能力诊断和边界验证。静态QA只在本次范围明确包含时纳入。
- 根据实际页面、产品资料、allowlist源码和隔离合成数据出题，核对账号权限与手工可完成性；不按助手工具清单选题，也不专挑其缺陷。
- 独立作者不读助手规划／修复实现、历史失败题、被测输出和既有金标；应用自身源码可读。新会话不自动等于独立，记录实际接触；去重由另一角色提供不含金标和失败信息的覆盖摘要或检查。不能隔离时标为实施者开发集。
- 不默认启动多agent。题目用于定位缺陷或指导修复后即属开发集，包括尚未运行但已用于修复的题；改写或换名称不构成独立新题。

## 分层出题

真实问法天然有歧义，判分又要求答案唯一；同一个作者既看得到数据又要写金标时，题目会被写成测试题：条件写全、编号列项、补齐边界说明。因此把“用户真正想要什么”和“用户会怎么说”分开写：精确意图放在隐藏场景里，歧义留在问法里，由金标列出可接受的理解。各层由独立会话完成，只拿本层需要的输入。分层产物（人设、场景、绑定、检查、评分）与题集同目录保存，不进入 `questions.json`。

1. **岗位人设。** 输入：当前账号可见的菜单树与页面标题、应用公开的模块说明；不看数据库、接口和已有题集。每个人设写明职责、常用菜单、日常与周期性工作。
2. **隐藏场景。** 输入：人设、菜单树、题集的锚定日期，以及每个菜单页面上可见的词汇（列表列、筛选项、表单字段、状态与字典选项的显示文字）；不提供记录和数据覆盖情况。每个场景写清：此人当时在做什么、精确意图、用户已知的信息、可接受的几种理解、待绑定的槽位及选取条件、涉及的相对时间。
   - 用户已知的信息只能是工作中合理知道的：名称、日期、金额等；一般不是类型ID、用户名或业务编号，除非场景里用户手上正拿着单据。
   - 只用页面词汇里有的字段和状态。
   - 多轮场景的后一轮可以指代前一轮的对象（“这个”“刚才那个”），但不编造助手已经给出的结果。
3. **实体绑定。** 由只读角色以同一账号完成。
   - 候选只取用户在对应页面上看得到的记录，在完整候选列表上随机抽取（见下文“反偏见采样”），并确认用户在该页面能找到它。日期、编号的写法取页面的实际显示。
   - 相对时间按锚定日期换算为具体日期范围，写入绑定记录。
   - 保存最小存在性证据；记录存在不等于任务在应用中可以完成。
   - 绑定失败时逐条记录，按原因处理，不为了绑得上而改变场景目标：
     - 数据缺少正常业务形态（模块有数据，但没有场景需要的状态或关联）：在隔离可重置环境里经应用接口补几条形态各异的记录，不只造恰好满足条件的一条；场景不变，补数后重新绑定，补数清单随题集保存。
     - 应用没有场景需要的字段或状态：附原因退回场景层修改。
     - 场景落在登记排除的菜单上（记录只能由外部发送或外部渠道产生）：为同一人设另写场景。
   - 绑定读取可能触发应用在读取时自带的写入（首次读取时生成默认数据、记录访问、标为已读等）。绑定结束后核对业务数据摘要，有变化就恢复基线。
4. **问法。** 输入：人设、绑定后的用户已知信息、风格说明和风格样例；看不到场景之外的系统内部、接口和数据库。有真实用户或所有者写的题时取一部分作样例，其余留作比较，二者不重复。按 [真实表达要求](references/realistic-questions.md) 写：像工作中随手问，保留必要信息，不编号，不替助手规划步骤，不追加查看或交接尾句；长名称只写用户会记住的部分，由此产生的歧义写进可接受的理解。
5. **独立检查。** 另一会话核对每题的目标、条件、提议值和指代是否与场景一致，表达是否易懂，标识是否符合用户认知。长度超过人写样例中位数两倍的逐条复核：能删就删，不能删的写明原因。发现问题直接修改对应的场景或问法，再核对语义；已有评分只对应评分时的题面。
6. **所有者评分。** 有所有者或熟悉业务的人参与时，冻结前逐题评“会／不太会／不会”，后两类写原因。评为“不会”的退回出错的那一层修改一次后再评；仍为“不会”的，为同一人设、同一类型另写场景。没有人参与时注明缺少这项检查。来源盲辨（AI题混入人写题，由未参与的人判断来源）可另做，结果单列。
7. **金标、资格与冻结。** 见“判定与交付”。

以下机制贯穿各层：

- **生成与验证分离。** 金标一律由同账号真实读取产生，不由出题会话写出；验证方只读题面与真实应用，不读出题各层的内部假设。
- **语义一致性。** 题面的每个条件词（“本月”“未审核”“看看”）映射到金标的一个已核验检查项，映射表随题集交付，机器可复核；映射不了的改写题面，或把该条件降为非判定性描述。
- **反偏见采样。** 对象从完整候选列表随机采样，禁止总取列表首条或字典序最小的记录；同一对象在全集中的出现次数有上限。出题开始时可用同一账号一次导出夹具数据，在本地采样与去重；资格核验前校验快照新鲜度（时间与账号指纹），过期重取。
- **边界题。** 缺值、多候选、不存在、无权限按场景模板加真实数据构造，金标记录应用的真实行为（实际提示语、实际拒绝码），不虚构。
- **程序化闸门。** 题集格式、表达规则的可程序化子集（句长、条件词覆盖、无操作链、无交接话术、无路线指定）、映射完备性与分布配额（口语化、多轮、相对时间、长度双峰、专项占比与题面不可区分性）由一个闸门脚本一次跑完。闸门只标记打回，**不自动改写**：重写回到对应的层并重建该题的映射表，防止改题后义务漂移。分布配额只报警、不拦截；闸门先对已冻结题集回放，误报可接受后才启用。
- **小批生成。** 覆盖矩阵先行，场景层按矩阵以不超过10题的小批产出；批间检查形态多样性（条件结构不同，不只换名），避免同质化。

题集只有两种身份：**开发集**与**独立题集**。开发集（含被实现会话接触过题面的题集）只能作开发证据；独立题集由不参与实现的出题会话冻结，可作独立验收，封存摘要写入题集目录的 `seal.json`（格式改写前后的摘要记 `reformatted` 字段）。盲测中的题集放 `.blind` 空文件或按查看器的排除规则登记，查看页不显示；盲测结束移除。封存后不可修改。开发集走轻流程：免冻结仪式、金标可用预期摘要、资格可抽样；独立与验收题集走全流程。

防泄漏纪律：出题会话不读实现分支的规划/修复代码与历史失败题；实现会话不读未封存题集（含开发集的题面与金标）。

## 表达与覆盖

出题、改写及表达审查时读 [真实表达要求与正反例](references/realistic-questions.md)。多数题用简短完整的一句话描述业务目标，保留必要对象、条件和值；不写操作链，不为变短删需求。直接页面／页签指令也合理；指代必须有真实页面或对话支持。人工提交等产品共有规则放判定，不默认追加“我来提交”“方便我查看”“先别提交”等背景或交接话术；用户确实明确提出的限制仍保留。

表达分布：10–15% 的题面是口语化的真实说法（自然连接词、礼貌修饰、“帮我”“顺便”式表达）——这是真实输入的一部分，不是故意写乱；多轮题占 15–25%，含“先看再改”与指代前轮列表结果（“就第2个……”）的形态；相对时间表达（“这周三”“上季度”“月底前”等）至少出现 2 题，按题集的锚定日期解析，绑定层写下换算后的日期范围并计入条件词映射，运行时被测各方都以锚定日期为当天；值的写法自然（“5箱”“19.9元”），不用接口格式。长度保持短查询为主、少量长明细的双峰分布，不人为拉平。

先列覆盖矩阵：岗位、模块、任务、控件、上下文、难度及预期结果，按真实使用频率加权（高频多出、高风险写入保底；没有使用频率数据时按岗位均分，不另行加权），并单列 Skill 专项子集及其占比；删除／归档等危险操作优先入边界题。覆盖条件查询／聚合、实际页面状态、部分预填／默认／清空／关联及相关混合任务；按本次范围取舍。自包含题为主，少量真实上下文；难度来自业务消歧、联动和恢复，不来自长文本、缺信息或无关目标堆叠。边界题单列，不抬高正向成功率；模板换名不算新场景。起始上下文与发起场景一致（`context.page.route` 取真实发起点：列表页、详情页，不总用首页）。

### Skill 路线专项与路由中立

独立与验收题集划出 **max(10%, 3题) 至 20%** 的 Skill 路线专项题；开发小套可豁免。

- 专项题验证 Skill 基座链路：声明核对、效果合同投影、完整可见卡片、新的一次性批准、单次派发、同 actor 回读、逐项回执。判定包含“确实经由 Skill 路线完成”（以审计事件与写入回执为准，不由题面指定），并至少覆盖四种形态：1 创建、1 修改、1 复合／写后读、1 写入边界（歧义目标或能力缺口的正确澄清／拒绝）。
- 其余题完全路由中立：按普通用户任务出题与评分，判定不查路由；等价路径原则延伸到执行路线，不因经过或未经过 Skill 路线加减分，也不为凑配额把普通题改标为专项题。
- 专项题题面与普通题不可区分：不出现路线词汇，冻结前抽查长度与句式分布，确保无法从题面分辨。
- 配额是覆盖下限（金丝雀），不是成功率样本：单套专项题不能用于估计 Skill 路线质量；质量结论用定向题集或跨套累计。
- 中立题的实际路由占比记为运行观测项。需要“非 Skill 路线不退化”的证据时，用同一套题、同一次运行加一个禁用 Skill 的配对臂解决，不为此改题目或判定。

## 判定与交付

编写或审查评分、资格、冻结及对照时读 [判定要求与评分维护](references/examples-and-rubrics.md)。

- 字段按 [题集的统一格式](references/question-format.md)：`id`、`prompt` 或 `turns`、`context`（起始页写 `context.page.route`）、`category`、`module`、`expected_outcome`（建议附 `semantic_obligations`）。金标只进 `cases.json`，由同账号实际应用核对，不能凭模型答案冻结；`questions.json` 只含模型可见内容。运行批次记 `runs.json`，通过口径为“完整成功”与“正确拒绝”。
- 写入题以应用终态判分：模拟用户只做产品请求的那一次确认，不改表单内容；细则见判定要求中的“写入题的终态判定”。
- 初态配置供装置建立环境；Agent只接收真实消息、实际观察与真实历史，不接收初态说明、金标、评分、内部ID或来源标签。多轮保留真实前轮状态。
- 表达审查（程序化闸门）→ 同账号原生资格 → 评分审查 → 冻结交付。脚本走通只证明可达；检查全部用户义务、非目标字段与零自动提交。未核实项标为待资格。
- 资格与金标按批处理：按实体分组、一次环境一批；每批先跑一道已知答案的哨兵题校验环境与账号，批内做状态重置断言（筛选器、缓存不跨题残留）。批失效只作废该批，不牵连整套。
- 金标来源分级：纯数据题（计数、单值、存在性）的金标可由同账号 API 读取产生；展示依赖题（完整名单、页面呈现、截断口径）须按产品展示合同或浏览器核验，不用裸 API 数据冒充。
- 每套题记录分段耗时（生成／闸门／资格核验／冻结），随题集目录保存；只用于定位瓶颈，不进入判定。
- 报告口径：正例与边界分开计数，错误完成（助手报告完成但与金标不符）单列；回合耗时报中位与 P95；记录模型请求数、token 与参考费用；各臂只在同一次运行内比较。
- 付费测量先冻结评测协议（题集、条件、冻结代码、规则、运行与报告字段，落成协议文件再运行），命令行设费用上限，并行度在协议中约定。
- 应用可做而助手缺能力计产品失败；权限等边界单列。装置异常／缺资格记阻塞，未运行记未运行。报告来源、覆盖缺口和封存摘要；独立验收题按约定封存，不向实现会话提前泄露题面。
- 新题A/B先声明比较变量，再冻结题目、金标、初态及各臂配置；除比较变量外尽量一致，记录其余差异，各臂从同一重置状态开始并在同一次运行内配对。报告分组成绩、调用、token、实际费用及单任务延迟，区分批量吞吐；开发集恢复不能证明新题架构收益，小样本或挑战集不能冒充生产成功率。

*维护：题集统一格式由 [references/question-format.md](references/question-format.md) 唯一定义，查看器与出题流程以此为准；产品合同或格式变化时更新本文件。*
