# Agent测评出题

检验助手能否完成真实用户需求，不把题目写成工具教程，也不因助手尚未支持而避开合理需求。本Skill不授权付费测评、产品修改或部署；付费测量的约定见"判定与交付"。

## 范围与独立性

- 沿用用户指定应用、范围和题数；未指定数量时按覆盖范围建议。题集按 [题集的统一格式](references/question-format.md) 编写（`cases.json`、`questions.json`、`runs.json`、`seal.json`、`.blind`）；存放位置与登记方式由查看器的运行环境约定，本Skill不作目录要求。区分开发回归、新题对照、能力诊断和边界验证。静态QA只在本次范围明确包含时纳入。
- 根据实际页面、产品资料、allowlist源码和隔离合成数据出题，核对账号权限与手工可完成性；不按助手工具清单选题，也不专挑其缺陷。
- 独立作者不读助手规划／修复实现、历史失败题、被测输出和既有金标；应用自身源码可读。新会话不自动等于独立，记录实际接触；去重由另一角色提供不含金标和失败信息的覆盖摘要或检查。不能隔离时标为实施者开发集。
- 不默认启动多agent。题目用于定位缺陷或指导修复后即属开发集，包括尚未运行但已用于修复的题；改写或换名称不构成独立新题。

## 全 AI 出题（生成-验证分离）

出题全程由 AI 完成，不设人工编写或人工审读环节；速度问题通过优化生成器流程解决。质量约束从"人眼"搬进"流程"，靠以下机制保证：

1. **生成-验证分离**：题面生成器与金标验证器必须是两个独立部分（独立脚本或独立会话），验证器只读题面与真实应用，不读生成器的内部假设。金标一律由同账号真实读取产生，从不由生成器"写出"。
2. **语义一致性自检**：题面每个条件词（"本月""未审核""看看"）必须映射到金标的一个已核验检查项；映射表随题集交付，机器可复核。无法映射的条件词要么改写题面，要么把该条件降级为非判定性描述。
3. **反偏见采样**：对象命名从夹具真实数据随机采样，禁止总取列表首条或字典序最小记录；同一对象在全集中出现次数有上限。
4. **边界题**（缺值/多候选/不存在/无权限）由生成器按场景模板+真实数据自动构造，金标记录应用的 Real 行为（实际提示语、实际拒绝码），不虚构。
5. **表达规范**：题面须通过表达审查规则（见下节与 references）的可程序化子集——句长、条件词覆盖、无操作链、无交接话术、无路线指定。
6. **程序化闸门**：题集格式、表达规则子集、条件词映射完备性与分布配额（口语化／多轮／相对时间／长度双峰／专项占比与题面不可区分性）由一个闸门脚本一次跑完。闸门只标记打回，**不自动改写**：重写回到生成器并重建该题的语义映射表，防止改题后义务漂移。分布配额为报警不拦截；闸门先对已冻结题集回放、误报可接受后才启用。
7. **夹具快照采样**：出题开始时用同一账号一次 dump 夹具数据，反偏见采样与去重在本地完成；资格核验前校验快照新鲜度（时间与账号指纹），过期重取。
8. **小批单遍生成**：覆盖矩阵先行，生成器按矩阵单遍产出题面、映射表与配额标签，以不超过 10 题的小批为单位；批间检查形态多样性（条件结构不同，不只换名），避免单遍生成的同质化与相关性错误。

题集只有两种身份：**开发集**与**独立题集**。开发集（含被实现会话接触过题面的题集）只能作开发证据；独立题集由不参与实现的出题会话冻结，可作独立验收，封存摘要写入题集目录的 `seal.json`（格式改写前后的摘要记 `reformatted` 字段）。盲测中的题集放 `.blind` 空文件或按查看器的排除规则登记，查看页不显示；盲测结束移除。封存后不可修改。开发集走轻流程：免冻结仪式、金标可用预期摘要、资格可抽样；独立与验收题集走全流程。

防泄漏纪律不变：出题会话不读实现分支的规划/修复代码与历史失败题；实现会话不读未封存题集（含开发集的题面与金标）。

## 表达与覆盖

出题、改写及表达审查时读 [真实表达要求与正反例](references/realistic-questions.md)。多数题用简短完整的一句话描述业务目标，保留必要对象、条件和值；不写操作链，不为变短删需求。直接页面／页签指令也合理；指代必须有真实页面或对话支持。人工提交等产品共有规则放判定，不默认追加“我来提交”“方便我查看”“先别提交”等背景或交接话术；用户确实明确提出的限制仍保留。

表达分布：10–15% 的题面是口语化的真实说法（自然连接词、礼貌修饰、“帮我”“顺便”式表达）——这是真实输入的一部分，不是故意写乱；多轮题占 15–25%，含“先看再改”与指代前轮列表结果（“就第2个……”）的形态；相对时间表达（“这周三”“上季度”“月底前”等）至少出现 2 题，由应用当前日期解析并计入条件词映射；值的写法自然（“5箱”“19.9元”），不用接口格式。长度保持短查询为主、少量长明细的双峰分布，不人为拉平。

先列覆盖矩阵：模块、任务、控件、上下文、难度及预期结果，按真实使用频率加权（高频多出、高风险写入保底），并单列 Skill 专项子集及其占比；删除／归档等危险操作优先入边界题。覆盖条件查询／聚合、实际页面状态、部分预填／默认／清空／关联及相关混合任务；按本次范围取舍。自包含题为主，少量真实上下文；难度来自业务消歧、联动和恢复，不来自长文本、缺信息或无关目标堆叠。边界题单列，不抬高正向成功率；模板换名不算新场景。起始上下文与发起场景一致（`context.page.route` 取真实发起点：列表页、详情页，不总用首页）。

### Skill 路线专项与路由中立

独立与验收题集划出 **max(10%, 3题) 至 20%** 的 Skill 路线专项题；开发小套可豁免。

- 专项题验证 Skill 基座链路：声明核对、效果合同投影、完整可见卡片、新的一次性批准、单次派发、同 actor 回读、逐项回执。判定包含“确实经由 Skill 路线完成”（以审计事件与写入回执为准，不由题面指定），并至少覆盖四种形态：1 创建、1 修改、1 复合／写后读、1 写入边界（歧义目标或能力缺口的正确澄清／拒绝）。
- 其余题完全路由中立：按普通用户任务出题与评分，判定不查路由；等价路径原则延伸到执行路线，不因经过或未经过 Skill 路线加减分，也不为凑配额把普通题改标为专项题。
- 专项题题面与普通题不可区分：不出现路线词汇，冻结前抽查长度与句式分布，确保无法从题面分辨。
- 配额是覆盖下限（金丝雀），不是成功率样本：单套专项题不能用于估计 Skill 路线质量；质量结论用定向题集或跨套累计。
- 中立题的实际路由占比记为运行观测项。需要“非 Skill 路线不退化”的证据时，用同一套题、同一次运行加一个禁用 Skill 的配对臂解决，不为此改题目或判定。

## 判定与交付

编写或审查评分、资格、冻结及对照时读 [判定要求与评分维护](references/examples-and-rubrics.md)。

- 字段按 [题集的统一格式](references/question-format.md)：`id`、`prompt` 或 `turns`、`context`（起始页写 `context.page.route`）、`category`、`module`、`expected_outcome`（建议附 `semantic_obligations`）。金标只进 `cases.json`，由同账号实际应用核对，不能凭模型答案冻结；`questions.json` 只含模型可见内容。运行批次记 `runs.json`，通过口径为“完整成功”与“正确拒绝”。
- 初态配置供装置建立环境；Agent只接收真实消息、实际观察与真实历史，不接收初态说明、金标、评分、内部ID或来源标签。多轮保留真实前轮状态。
- 表达审查（程序化闸门）→ 同账号原生资格 → 评分审查 → 冻结交付。脚本走通只证明可达；检查全部用户义务、非目标字段与零自动提交。未核实项标为待资格。
- 资格与金标按批处理：按实体分组、一次环境一批；每批先跑一道已知答案的哨兵题校验环境与账号，批内做状态重置断言（筛选器、缓存不跨题残留）。批失效只作废该批，不牵连整套。
- 金标来源分级：纯数据题（计数、单值、存在性）的金标可由同账号 API 读取产生；展示依赖题（完整名单、页面呈现、截断口径）须按产品展示合同或浏览器核验，不用裸 API 数据冒充。
- 每套题记录分段耗时（生成／闸门／资格核验／冻结），随题集目录保存；只用于定位瓶颈，不进入判定。
- 报告口径：正例与边界分开计数，错误完成（助手报告完成但与金标不符）单列；回合耗时报中位与 P95；记录模型请求数、token 与参考费用；各臂只在同一次运行内比较。
- 付费测量先冻结评测协议（题集、条件、冻结代码、规则、运行与报告字段，落成协议文件再运行），命令行设费用上限，并行度在协议中约定。
- 应用可做而助手缺能力计产品失败；权限等边界单列。装置异常／缺资格记阻塞，未运行记未运行。报告来源、覆盖缺口和封存摘要；独立验收题按约定封存，不向实现会话提前泄露题面。
- 新题A/B先声明比较变量，再冻结题目、金标、初态及各臂配置；除比较变量外尽量一致，记录其余差异，各臂从同一重置状态开始并在同一次运行内配对。报告分组成绩、调用、token、实际费用及单任务延迟，区分批量吞吐；开发集恢复不能证明新题架构收益，小样本或挑战集不能冒充生产成功率。
