# 题集的统一格式

本文件是题集统一格式的唯一定义；查看器（题集总览页及其构建脚本）与出题流程都以此为准。题集的存放位置与发现、登记方式由查看器的运行环境约定，本格式不作目录要求。

一套题是一个目录，目录名就是题集名。目录里：

| 文件 | 是否必需 | 内容 |
|---|---|---|
| `cases.json` | 有金标时必需 | 题目加金标。给人和判定方看，不给模型看 |
| `questions.json` | 要交给模型运行时必需 | 只含模型可见的内容：题面和起始状态 |
| `runs.json` | 有运行记录时必需 | 这套题的各次运行，见下文“运行记录”。跑完一套题即在它的目录里登记一条 |
| `seal.json` | 可选 | 封存摘要 |
| `.blind` | 可选 | 空文件。有它，查看页面不打开也不显示这套题 |

两个文件都可以是题目列表，也可以是一个对象，题目列表放在它的 `questions` 字段里，其余字段是题集自己的说明（`schema_version`、`description`、`environment` 等，不限）。对象里有字符串字段 `label` 时，页面用它做题集的显示名。

目录里的题集文件如果是指向另一套题的链接，这个目录是那套题的一次重跑，不算一套题。

## 一道题

| 字段 | 是否必需 | 写法 |
|---|---|---|
| `id` | 必需 | 题号，套内唯一 |
| `prompt` | 与 `turns` 二选一 | 单轮题的题面，字符串 |
| `turns` | 与 `prompt` 二选一 | 多轮题的各轮题面，字符串列表，按顺序 |
| `context` | 可选 | 起始状态。起始页写在 `context.page.route` |
| `category` | `cases.json` 里建议有 | 题型 |
| `module` | 可选 | 所属模块 |
| `expected_outcome` | `cases.json` 里有金标的题必需 | 金标，任意 JSON。是对象并且有字符串字段 `summary` 时，页面先显示它。多轮题各轮的预期放在 `expected_outcome.turns` |
| `semantic_obligations` | 可选 | 字符串列表：答复必须做到的各项 |

其它字段不限，原样保留。`questions.json` 里的题只应有 `id`、`prompt` 或 `turns`、`context`，以及运行装置需要的字段；金标不进这个文件。

## 运行记录

题集目录里的 `runs.json` 是一个列表，每项是这套题的一次运行：

| 字段 | 是否必需 | 写法 |
|---|---|---|
| `id` | 必需 | 批次标识，套内唯一 |
| `label` | 建议有 | 页面上显示的名字，写清版本、范围和判定来源 |
| `path` | 有逐题记录时必需 | 运行目录，相对查看器根目录的相对路径。只有入库判定文件、没有逐题记录时可省略，页面按判定显示各题通过与否与理由，答复留空 |
| `judgement` | 可选 | 判定文件，相对查看器根目录的相对路径。键是 `<臂名>/<题号>`，值有 `verdict` 和 `reason` |
| `judged_as` | 有 `judgement` 时必需 | 判定文件里这一批用的臂名 |

运行目录里每道题一份记录，三种放法都认：`<题号>/result.json`、`<题号>/worker-receipt.json`、`attempts/<题号>.json`。记录里读这些字段：`answer`（或各轮 `turns[].answer`）、`status` 或 `outcome`、`passed` 或 `success`、`reasons`、`elapsed_s` 或 `seconds`。有 `judgement` 时，通过与否以判定文件为准：`完整成功` 和 `正确拒绝` 算通过。

运行目录通常在不入库的 `raw/` 下。换一台机器后页面仍显示题目，批次标为“无记录”。
