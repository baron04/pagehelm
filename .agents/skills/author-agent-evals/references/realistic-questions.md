# 真实用户表达：要求、正例与反例

这些是用于学习和审查的合成例子，不是冻结题集，也不证明对应功能已经接入。出题时须核对实际应用、账号和合成数据；复制示例或仅换名称不构成独立新场景。独立作者可读此通用规范并建立本次金标，不能读旧题金标、历史失败或被测输出。

## 要求

1. **说清需求，保留必要信息。** 通常一句话包含对象、目标和必要条件／值。对象可由真实当前页面或前序对话提供；没有上下文时不能刻意省略，从首页提问的题没有页面上下文。不要要求每个问题都像正式需求文档。
2. **简洁靠删废话，不能靠删需求。** 少写背景和重复交接说明，保留明确要求的金额、日期、字段与结果。用户真要多字段或明细，合理长度可以更长；不设硬字数上限。
3. **让Agent规划路径。** 普通题写“我要做什么”，不给导航层级、按钮顺序、内部工具及参数。直接打开页面／页签、翻页或清空也是正常需求，但整套题不能主要是操作脚本。
4. **复杂性来自业务。** 用真实消歧、条件组合、关联、联动、多轮和恢复提高难度。不能靠长提示、多个无关目标、API术语或缺信息制造难度。
5. **省略信息须有明确用途。** 故意缺值或存在多候选时，作为真实澄清场景，按澄清评分；不能给普通成功题配置作者脑中才知道的唯一目标。
6. **题干与判定分开。** 权限、初态、目标快照、评分检查和产品共有人工提交规则放评测配置，不塞进用户话术。用户确实明确提出的限制仍保留。
7. **审查整个题集。** 自包含问题为主，上下文问题少量；按任务范围覆盖业务目标、直接操作和混合任务。避免大量同模板换名字；单项诊断集可以只测一种能力，不能据此声称广覆盖。
8. **值与时间按用户说法写。** 数量、金额、日期用自然的用户写法（“5箱”“19.9元”“这周三”），不用接口格式、字段名或编码；相对时间按题集的锚定日期解析，并计入条件词映射。
9. **只写用户记得的。** 用户一般记不住类型ID、用户名和业务编号，除非手上正拿着单据；长名称只写会记住的部分（品牌、型号或关键词），由此产生的多个候选按澄清场景处理。
10. **不带测试痕迹。** 题面不出现“合成”“测试”“小测”之类的字样或测试专用名称，数据里有这类名称的记录不选作题目对象。不为让金标唯一而在题面补说明（“不含今天”“要全部，别只给几条样例”“按某页显示的时间”），歧义写进金标的可接受理解；用户真会这样限定的除外。

## 正面示例

| 类型 | 可以像用户这样问 | 为什么合理 |
| --- | --- | --- |
| 普通查询 | 青禾包装的商机有哪些 | 对象和需求完整，返回字段由正常产品体验决定 |
| 指定结果 | 青禾包装的商机名称、金额和预计成交日期 | 用户确实要这些字段，短表达仍保留全部要求 |
| 简单计数 | 未审核销售订单有几张 | 用户问数量，无需加金额等额外结果；需核对应用中销售订单指向是否明确 |
| 直接导航 | 打开云杉机电的客户详情 | 用户确实要看这个页面，直接操作题有价值 |
| 业务目标 | 我想给云杉机电补条跟进，内容是周五回访 | 助手自行发现目标和表单入口，不需要用户描述按钮 |
| 条件页面 | 打开10月创建且未审核的采购订单 | 条件完整，助手决定筛选方法；日期年份由正常时间上下文确定 |
| 短而复杂 | 打开10月创建且未审核的采购单里金额最高的那张 | 难度来自筛选、极值及记录定位；并列情况需真实澄清或呈现 |
| 部分预填 | 新建客户南星，行业是IT，级别是B | 给必要业务值，不要求填写全部字段或重复人工提交规则 |
| 修改与清空 | 清空云杉机电的电话 | 对象和字段明确，保留其它字段 |
| 混合目标 | 云杉机电原电话是多少？改成13800000000 | 原值答复和新值预填均是用户真实目标 |
| 连贯明细 | 新建采购单，供应商是远舟，纸箱10个、胶带5卷 | 信息更长但属于同一个业务目标，不能为变短删除明细 |
| 写后混合 | 给青杉机电记一条跟进，内容是周五回访，完了告诉我它的下次联系时间 | 写入与回报是同一请求的两项义务，逐项核对 |
| 口语化目标 | 帮我把云杉机电的电话改成13800000000，谢谢 | 礼貌词与口语连接是真实说法，判定不受影响 |
| 相对时间 | 看看上季度成交的客户有哪些 | 时间按题集的锚定日期解析；“看看”是普通请求语气，不是含糊 |
| 按人名而非账号 | 把王敏的角色改成销售经理 | 用户知道同事姓名，不知道登录用户名或用户ID |
| 有真实页面上下文 | 把邮箱也清空 | 仅当当前编辑对象或前序对话真实明确时成立；否则应澄清 |
| 静态QA（若纳入范围） | 保存数据源时会测试数据库连接吗 | 对象完整，需要实际源码调用链，不提供答案线索 |

上述问题并非都应直接成功。歧义、权限和真实应用规则决定是否需要澄清或拒绝；资格和评分必须相应核对。

## 反面示例及调整方法

| 有问题的题干／设计 | 问题所在 | 调整方法 |
| --- | --- | --- |
| 保存会测连接吗？（无页面／历史） | 只追求短，不知道哪个对象和连接 | 补对象；若真是当前数据源编辑页，保留为上下文题并配置真实页面 |
| 把它改了。（金标要求改某客户电话） | 隐藏对象、字段和值，金标比用户请求更具体 | 提供真实上下文和必要值，或改为澄清题 |
| 点击CRM菜单→客户→搜索云杉→详情→编辑→第三个输入框 | 已把规划答案写进题目，字段位置也脆弱 | 写客户与业务修改目标；不要提供点击链 |
| 打开云杉机电的客户详情，方便我查看 | 追加的查看说明没有增加用户需求 | 简化为打开云杉机电的客户详情；“请”等正常礼貌词不必机械删除 |
| 打开crm/customer页面，调用prepare_form，把source设为2 | 让业务用户讲内部实现，测试工具协议而非产品目标 | 使用页面业务名称、可见选项与用户目标；开发者源码题则另行设计 |
| 请用Skill流程给云杉机电记一条跟进 | 把执行路线写进题面，测路由而非业务目标 | 只写业务目标；路线验证由专项题的审计断言承担，不由题面指定 |
| 新建客户南星，行业是IT，级别是B，填好后我来提交，先别提交 | 为普通题追加产品共有交接说明，掩盖助手默认流程缺陷 | 只写业务目标和值，人工提交放隐藏判定；真实用户的明确限制保留 |
| 查客户、统计订单、建项目、解释退款再打开会员页面 | 用无关目标堆叠制造难度 | 拆分；真正有业务关联的混合需求保留 |
| 简化“商机名称、金额和日期”为“商机有哪些”，仍要求回答金额和日期 | 改题后金标未同步，形成隐含要求 | 改写保持语义；若用户授权改变目标，则新建版本同步判定 |
| 题目仅问“有哪些商机”，金标要求走指定API、打开指定页签 | 评分限制实现路径，还增加用户未要求的页面动作 | 接受符合请求的等价路径，完整结果按实际用户需求判断 |
| 把用户名 wangmin01 的角色改成销售经理 | 用户一般不记得同事的登录用户名 | 用姓名称呼；同名时作为澄清场景 |
| 大多数题都是“打开X”“点击Y”，其余只是换客户名 | 题干各自可能合理，但整体不覆盖真实业务规划 | 加入短业务目标、条件查询、部分预填、联动及少量真实上下文 |
| 把“测试数据临时”这个角色删了 | 对象名称暴露测试数据，真实用户碰不到 | 换成数据里自然命名的对象；没有就补自然命名的数据 |
| 最近30天（不含今天）的退款有几笔 | 括号是评分方为让金标唯一补的说明 | 写“最近30天的退款有几笔”，两种截止日写进可接受理解 |
| 访客为0的商品全拉出来，要全部，别只给几条样例 | 后半句是评分方担心的交付缺陷，不是用户需求 | 写“访客为0的商品有哪些”，列全由判定要求保证 |
| 按订单页显示的时间，今天10:00到10:10改过哪些订单 | 为测试造的十分钟窗口加页面提示，工作中不会这样问 | 换成工作中真会问的范围，如“今天上午改过哪些订单” |
| 一套题里菜单排序、组件路径、字典新增各占几道 | 每题都说得通，但这些是偶尔才做的配置，整套偏离日常工作 | 按岗位日常工作的频率重排，配置类只留少数 |

## 逐题审查与整套检查

冻结前逐题检查：

- 用户为什么会向助手提出这个需求？是否节省查找、判断或操作，而非照着页面抄一套脚本？
- 这件事是不是这个岗位常做的？频率排在后面的任务是否只占少数？
- 题面和对象名称里有没有“合成”“测试”这类痕迹，或为让金标唯一补的说明？
- 不看隐藏金标，只读题干与真实可见上下文，能否知道应交付什么，或明确需要澄清什么？
- 题面里的标识（ID、用户名、业务编号、完整长名称）是用户真的会知道和写出的吗？
- 长度超过人写样例中位数两倍的，是否已逐条复核？
- 是否出现不必要的操作链、测试说明、内部参数或金标线索？是否无理由追加“我来提交”“方便我查看”“先别提交”等话术？
- 去掉某段话会不会改变对象、范围、值或交付要求？若会，不能当废话删掉。
- 所有最低必过项能否追溯到用户需求或产品共有合同？是否漏了混合任务的答案／页面／预填义务？
- 题面分布是否符合本次配额：口语化占比、多轮占比、相对时间是否出现、长度是否双峰、开头句式是否过度模板化；专项题与普通题在长度和句式上是否无法区分。
- 改写题面后，实体（或简称）、条件、目标值、轮数与起始路由是否仍与绑定及金标同步。
- 有真实用户样本（演示或使用记录）时做一次表达分布对照（长度、口语度、多轮占比）；没有样本不硬造，保持“不宣称生产准确率”的声明。

审查时标记“保留／改写／上下文题／澄清题”及具体原因，使用现有题集元数据或内部审查表，不把这些标记传给被测Agent。整套再检查覆盖分布和重复模板。表达审查与实际应用资格均完成后冻结；不能仅凭字数、语法或模型自评认定题集真实。
