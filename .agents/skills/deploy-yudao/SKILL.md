# 芋道部署

入口已经固定，不需要重新搜索发布方式：

- 仓库根目录 `./deploy`：构建当前助手并发布到本机配置的服务器。
- `./deploy check`：只读检查本地配置、固定缓存及服务器前置条件。
- `./deploy status`：查看线上发布清单与实际 Runtime 摘要。

先读仓库的 `docs/guides/deploy-yudao.md`。普通发布使用根入口；`examples/yudao/deploy/cloud/deploy.sh` 是其底层实现。

## 执行约定

1. 用户已要求部署时，运行 `./deploy` 并等待退出结果；用户仅要求优化流程或核验时，使用 `check` 或 `status`，不切换线上版本。
2. 私有目标配置在 Git 忽略的 `deploy.local.toml`，只包含 SSH 目标和公开站点地址。缺失时先读模板，并向用户获取确实缺少的信息；不要推断服务器或索要密码、私钥。
3. 本地应用缓存固定为 `.q0-cache/yudao`。不要创建日期、版本或任务后缀目录，也不要通过切换其他缓存来掩盖版本检查失败。上游源码和 Java 补丁变化需要先重建对应基础产物，具体命令在指南中。
4. 模型密钥保留在服务器 `/opt/yudao/agent.env`。检查文件是否存在即可；不读取、回传或提交其内容。
5. 以命令最终退出码、线上发布清单和 Runtime 摘要判断是否部署成功；失败不能汇报为已部署。不自动反复发布。若连接中断或结果不确定，先运行 `./deploy status` 确认当前版本，再决定后续操作。

发布会重启助手，可能中断执行中的对话。正常发布不恢复数据、不运行 seed、不删除数据卷；数据库升级与快照恢复须作为单独任务处理。健康检查不调用模型，也不证明登录后的用户问题已验收通过。
