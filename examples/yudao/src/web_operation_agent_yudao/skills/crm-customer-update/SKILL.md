# 修改客户资料

**适用目标**：把用户明确要求的资料变化落到一条既有 CRM 客户上，其他已读业务资料保持不变。

**相邻目标**：容易混淆的目标是修改联系人资料（目标记录是联系人，不是客户）；放入公海、领取、锁定、成交状态（状态动作不能用资料修改替代，分别见 crm-customer-pool-release、crm-customer-receive、crm-customer-lock、crm-customer-deal-status）；修改线索资料（线索是另一实体，见 references/crm-erp-identity.md）；修改 ERP 客户（进销存往来单位）；记录跟进（跟进只更新主对象的跟进字段，是独立动作）。负责人转移是当前应用未提供的能力，不是本 Skill 能替代的动作。

**所需用户信息**：确切的目标客户（完整名称或已核实候选）；要修改的字段和确切新值。联系方式、正文、备注、地址等文本保留完整原文；可选资料按用户原文提供，缺省不猜。

**利用当前事实的流程**：
1. 按当前账号索引定位确切客户；同名时按 references/disambiguation.md 用关联客户、负责人或候选引用消歧，由用户选定，不任选一条。
2. 需要时先用当前只读能力核实字段当前值和字典标签；地区按 references/hierarchy-paths.md，行业/等级/来源等标签以当前字典为准，不猜编号。
3. 组成只含用户要求变化的提案；接口必填的当前值（如名称、客户编号、负责人编号）由应用读取并作为保留项进入审批卡，这些保留项对用户可见。
4. 展示确切对象、完整变化和保留项，等待新的批准；批准前重新核对有关前值，发现变化即停止。该检查不提供原子并发锁。

**完成条件**：同账号回读确认要求的变化已写入、已读取的其他业务资料未变；任一义务未证实即不称完成，保留不确定状态并停止，不自动重试，也不能通过浏览器保存绕过审批。本 Skill 只承担客户资料修改，不执行相邻动作：公海、领取、锁定、成交由已安装的相邻 Skill 承担，按完整请求选择对应 Skill 并使用已有结果依赖；负责人转移等当前应用实际未提供的能力才报告缺口。不能删减请求后按资料修改宣布完成。用户要求的后续查询或打开档案仍属于完整请求。
