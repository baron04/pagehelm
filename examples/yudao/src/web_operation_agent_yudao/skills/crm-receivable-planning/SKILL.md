# 安排合同回款计划

**适用目标**：仅在用户明确要求创建未来应收的回款计划或分期计划时使用；查询与页面定位支持该目标。

**相邻目标（严禁越权代建）**：容易混淆的目标是记录实际回款或收款（回款计划不是实际收款记录，不创建到账或支付；当用户要求登记/新建实际回款且合同缺少对应回款计划或当前账号无权限时，**严禁擅自调用 `crm_receivable_plan_create` 补建回款计划**，应直接向用户如实说明原因或 `need_input` 确认）；创建或修改合同（本目标只读合同，不创建合同）；修改客户资料（客户由合同派生，不由本目标改写）。

**所需用户信息**：确切合同、确切负责人、应用时区的回款时间和金额（元）。回款方式来自当前字典；提醒天数、备注可选，不编造缺项。

**利用当前事实的流程**：
1. 合同按当前确切业务名称或完整候选引用定位，按 references/disambiguation.md 消歧；负责人从当前用户列表解析。
2. 客户从合同派生，期数按该合同当前最大期数加一；提醒日期由回款日期减提醒天数。这些由应用派生，不让模型提供与合同不一致的值。用户未要求具体期数时卡片说明“由应用生成”。
3. 完整输入、合同和客户关系、派生期数/提醒及权限效果进入新审批；为指定负责人建立计划 OWNER 权限。

**完成条件**：批准后核对合同、负责人和计划序列未变化，只派发一次；按返回编号同账号核对字段、客户、期数、提醒和权限，实际回款编号须仍为空。指定他人负责可能使当前账号无法回读，不能声称全部验证成功；无法核实、超时或部分执行保留不确定状态并停止，不自动重试。创建到账、支付或合同不在本目标内。只问结构或流程时解释并读取；预填时交接表单；后续查询或页面交付仍属于完整请求，不能通过页面保存绕过批准。
