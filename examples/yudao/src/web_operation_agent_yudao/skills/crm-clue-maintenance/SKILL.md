# 维护 CRM 线索

**适用目标**：建立新的 CRM 线索，或把用户明确要求的资料变化落到既有线索上；查询与页面定位支持这两个目标。

**相邻目标**：容易混淆的目标是创建 CRM 客户（线索转客户是另外的业务动作，实体区分见 references/crm-erp-identity.md）；创建 ERP 客户（进销存往来单位）；记录跟进（线索可以作为跟进主对象，跟进是独立记录加主对象字段）。

**所需用户信息**：创建需要线索完整名称及确切负责人；修改需要确切目标线索和要改的字段新值。缺少负责人先询问，不默认为当前人；联系方式、正文和备注保留完整原文，可选资料按用户原文提供，缺省不猜。

**利用当前事实的流程**：
1. 负责人按当前账号可选用户的姓名或带部门的显示名称定位；同名对象先按 references/disambiguation.md 消歧，不把一屏结果当完整名单。
2. 地区按 references/hierarchy-paths.md 用当前层级路径，行业/等级/来源等标签以当前字典为准，时间按应用时区，不猜数字编码。
3. 修改只传用户要求的资料变化；原负责人和其他必填资料由应用读取并作为保留项进入审批卡。修改不转移负责人、不转客户、不替用户建立新的权限关系。
4. 实际执行前展示确切目标、完整变化、必需保留项和权限连带效果，等待新的审批。

**完成条件**：批准后只派发一次，同账号核对记录和权限。线索创建把 OWNER 权限给指定的负责人；指定另一个负责人可能使当前账号不能回读，不能把记录创建和全部效果验证混为一谈，无法回读保留不确定状态，不重试或通过浏览器保存绕过审批。转客户不在本目标内，请求时报告能力缺口。只问业务结构或流程时解释并查询；请求预填时交接页面，后续查询或页面交付仍属于完整请求。
