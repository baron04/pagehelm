# 通用记录编译写入与状态关联维护

**适用目标**：在各业务域通过常驻通用类型化工具完成受编译期写契约约束的数据变更：扁平记录新建（`create_record`，页面合法初始默认值将标以`（页面默认值）`并公开上卡）、单表或 1–2 层嵌套明细单据修改（`update_record`）、两态互逆启停/上下架切换（`toggle_record_status`）以及角色/分组等多对多关联集合分配（`assign_record_relations`）。

**相邻目标**：已有专属领域操作（如部门 `system_dept_create`、岗位 `system_post_create`、CRM 客户/跟进/回款计划、ERP 仓库/客户/供应商/单据审批、OA 公告、秒杀关闭等）时优先使用对应专用操作；未纳入编译建表的含密码账号、多行明细新建草稿或复杂审批流起草，改走页面表单预填与提交按钮高亮交接（不代点提交）。

**所需用户信息**：明确目标记录名称/单号及所属实体、待新建或修改的字段明确新值、目标开关状态（启用/停用等）或完整关联列表；新建必填项或父外键上下文缺失时先向用户询问，多条同名记录须由用户澄清，禁止凭空猜值。

**利用当前事实的流程**：
1. 先通过当前账号只读列表/详情接口（或 `find_record` / `call_api`）核实目标记录、现有保留字段及外键关联候选项；追加备注或数组前须读出原值并在其后拼接，不得覆盖原值。
2. 直接调用 `create_record` / `update_record` / `toggle_record_status` / `assign_record_relations`（或 `propose_operation`）生成写入提案，关联字段按真实名称、层级路径或当轮已读核验候选标识传参。
3. 所有字段来源与影响范围（含页面默认值标注与保留字段）在批准卡完整展示，等待用户单次批准；派发前由程序重读核验，无误后单次提交。

**完成条件**：只派发一次并由当前同一账号回读核对新建结果、修改字段及未改动保留项一致；拒绝或结果不确定（timeout/indeterminate）立即停止并保留审计记录，绝不自动重试。纯查询、解释流程或仅要求预填表单不触发写入提案。
