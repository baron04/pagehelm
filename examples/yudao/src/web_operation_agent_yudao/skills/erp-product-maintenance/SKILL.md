# 维护 ERP 产品

**适用目标**：建立新的 ERP 产品（进销存物料档案），或把用户明确要求的变化落到既有产品上；查询与页面定位支持该目标。

**相邻目标**：容易混淆的目标是维护商城品牌、创建商城分类（商城侧定义，区分见 references/mall-erp-identity.md）；创建计量单位或产品分类（关系对象，本目标只解析引用，不用创建产品代替创建单位）；修改库存或单据（未要求的排序、库存、SKU、商城上架或采购单不附带执行）。

**所需用户信息**：创建需要完整名称、条码、分类、单位和明确开启状态；修改需要确切目标产品和要改的字段新值。可选价格、重量、保质期、规格、备注按用户原文提供；已有图片输入不触发上传或下载。

**利用当前事实的流程**：
1. 修改时按确切名称定位目标产品，同名时按 references/disambiguation.md 消歧，由用户选定；分类与单位从当前应用解析，分类同名时按 references/hierarchy-paths.md 用完整层级路径消歧，单位取当前账号可获得的选项。
2. 条码、价格、重量等数值与编码约定见 references/erp-units.md。
3. 修改只表达要求的 changes；其他必填字段读取当前值并展示为保留项，非目标业务资料核对保持。
4. 缺项、歧义和能力缺口在审批前解决，不省略完整请求。执行展示确切产品、变化、必需保留项、分类和单位名称，等待新的审批。

**完成条件**：批准后只写一次，按返回编号同账号回读全部字段。审批期间关系或前值变化即停止；该检查不是原子并发锁；超时或未知效果不重发。只问流程时说明步骤，预填请求交接表单，后续查询或页面交付仍属于完整请求。
