# 创建系统部门

**适用目标**：在组织结构中建立一条新的部门记录，挂在用户指定的父级之下。

**相邻目标**：容易混淆的目标是创建系统岗位（岗位档案，见 system-post-creation）；角色与权限管理（本动作不变更权限）；CRM 联系人职位（资料文本）。区分见 references/org-records-identity.md。

**所需用户信息**：部门完整名称、确切父部门、排序和明确的开启状态；负责人可选。缺父层级先询问；用户明确要求顶层时表达为“根节点”，未提到父级不能猜顶层。

**利用当前事实的流程**：
1. 父部门按 references/hierarchy-paths.md 用当前完整路径消歧，不猜编号；可选负责人从当前用户列表解析，不能猜身份。
2. 同一父部门下名称唯一由应用校验；名称保留完整原文。
3. 父层级、负责人及全部字段进入审批，等待新的完整批准。

**完成条件**：批准后单次派发，同账号回读核对新建部门的名称、父层级和排序。创建部门不分配用户、岗位、角色或权限，请求这些效果时报告能力缺口。应用拒绝如实返回；超时或不确定写入不自动重试。用户问流程时解释输入和校验步骤；预填请求交接表单；后续查询或页面交付仍属于完整请求。
