# 创建或修改系统部门

**适用目标**：在组织结构中建立新的系统部门记录（`system_dept_create`），或修改既有系统部门的名称、上级部门、负责人、排序、状态、电话与邮箱（`system_dept_update`）。

**相邻目标**：容易混淆的目标是创建或修改系统岗位（见 `system-post-creation`）；角色与权限管理（本动作不变更权限）；CRM 联系人职位（资料文本）。区分见 references/org-records-identity.md。

**所需用户信息**：创建需要部门完整名称、确切父部门、排序和明确的开启状态（负责人、电话、邮箱可选；明确要求顶层时父部门表达为“根节点”，未提父级先询问不猜顶层）；修改需要既有部门的确切名称及要改的字段新值。

**利用当前事实的流程**：
1. 父部门与既有目标部门按 references/hierarchy-paths.md 用当前完整路径或唯一名称消歧，不猜编号；负责人从当前用户列表按显示名解析。
2. 修改只表达用户要求的 `changes`，其余必填项读取原值作为保留项；同一父部门下名称唯一由应用校验。
3. 父层级、负责人及全部目标变化进入审批，等待新的完整批准。

**完成条件**：批准后单次派发，同账号回读核对部门字段及保留项。不分配用户、岗位、角色或权限，请求这些效果时报告能力缺口。超时或不确定写入不自动重试。只问流程时解释步骤；预填请求交接表单；后续查询或页面交付仍属于完整请求。
