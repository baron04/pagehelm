# 记录和核对跟进

**适用目标**：为一条确切的主对象新增跟进记录，并核对记录本身与主对象、关联成员的跟进副效；查询与页面定位支持该目标。

**相邻目标**：容易混淆的目标是修改客户资料或修改联系人资料（跟进不改主对象的一般资料字段，不能用来替代资料修改）；为客户新增联系人（创建档案记录，不是跟进）。跟进的客户、联系人、商机和合同是不同的主对象类型，不能互相替代。

**所需用户信息**：主对象的类型与确切名称；跟进方式、完整跟进内容和下次联系时间。时间按应用当前时区解释，跟进方式以当前字典为准；缺少信息先补齐，不编造用户没说的日期或内容。用户明确要求关联联系人或商机时，需要完整的成员名称集合。

**利用当前事实的流程**：
1. 先确定主对象类型和确切对象，按 references/disambiguation.md 消歧；页面索引可能只有主对象页面，没有独立的跟进记录页面。
2. 原生创建会先插入记录，再按主对象类型更新跟进信息：客户、线索更新最近联系时间、下次联系时间、最近跟进内容、已跟进标志；联系人无已跟进标志；商机无最近跟进内容；合同只更新最近联系时间。最近联系时间由应用在执行时产生；下次时间和正文使用本次记录的值。这些属于同一次业务操作的连带效果，不承诺原生未更新的字段。
3. 关联成员保留完整集合，用当前账号读取的完整候选名称定位；关联成员的下次联系时间会一并改为本次时间，这是额外目标上的写效果，准备和派发前都核对成员的 OWNER/WRITE 权限。审批同时展示全部成员及时间。
4. 展示记录、主对象和关联成员的完整效果，等待新的批准。

**完成条件**：批准后只派发一次，分别回读记录、主对象和每个关联成员的完整集合与下次联系时间，不仅核对主对象。记录已插入但后续失败时报告可核实与未核实部分，停止后续操作，不重新插入。附件、图片等未支持内容报告能力缺口，不得用空数组替代或把地址塞进正文后声称完成。核实完成后可继续打开主对象或查后续事项，页面能力由当前应用决定；解释流程、查询结构或查看历史时不用写审批。
