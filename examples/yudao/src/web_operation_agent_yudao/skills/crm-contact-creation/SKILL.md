# 在客户下新增联系人

**适用目标**：在一条既有 CRM 客户下建立新的联系人记录，客户归属由用户指定并核实。

**相邻目标**：容易混淆的目标是创建客户（目标产物是客户本身，见 crm-customer-creation）；修改联系人资料（既有记录的变化，不是新建）；记录跟进（跟进记录是独立实体，不能代替创建联系人）；ERP 客户或供应商的“联系人”是资料文本（references/crm-erp-identity.md）。

**所需用户信息**：联系人的完整姓名和确切的所属客户（完整名称或已核实候选）。联系人的职位是资料文本、不是系统岗位（references/org-records-identity.md）；可选资料按用户原文提供，缺省不猜。

**利用当前事实的流程**：
1. 按当前账号索引定位所属客户；同名时按 references/disambiguation.md 用关联负责人或候选引用消歧，由用户选定，审批时显示真实客户名称和编号。
2. 地区等层级引用按 references/hierarchy-paths.md 用当前树的名称或完整路径，性别等字典标签以当前应用为准。
3. 当前创建操作把负责人设为当前账号，并为其建立 OWNER 数据权限；申请表保留负责人字段，权限归属以当前操作人为准。指定其他负责人的请求在写前拒绝，不能省略该条件后按当前账号建档。
4. 展示全部字段、确切所属客户、新建效果和权限连带效果，等待新的完整审批。

**完成条件**：批准后只派发一次，同账号按返回编号回读联系人字段、客户归属、负责人字段与当前账号的 OWNER 权限；任一未证实即不称完成。指定了其他负责人的请求未获支持即不称完成。用户要求的后续查询、打开档案或查看其他联系人仍属于完整请求，不能省略；超时或无法核实保留不确定状态，不自动重试。
