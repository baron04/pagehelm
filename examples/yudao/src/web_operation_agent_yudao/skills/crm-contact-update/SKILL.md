# 修改联系人资料

**适用目标**：把用户明确要求的资料变化落到一条既有 CRM 联系人上，客户归属、负责人和其他已读业务资料保持不变。

**相邻目标**：容易混淆的目标是修改客户资料（目标记录是客户本身）；为客户新增联系人（创建动作，见 crm-customer-creation）；记录跟进（跟进记录和主对象跟进字段是独立动作，不能代替资料修改）；修改线索资料。岗位与联系人职位的区分见 references/org-records-identity.md，实体区分见 references/crm-erp-identity.md。

**所需用户信息**：确切的目标联系人（完整名称，必要时含所属客户）；要修改的字段和确切新值。联系方式、正文、备注保留完整原文；可选资料按用户原文提供，缺省不猜。

**利用当前事实的流程**：
1. 先按确切姓名查找联系人；同名时按 references/disambiguation.md 用关联客户或负责人消歧，由用户选定。
2. 读取当前资料，确认要改的字段及新值；地区按 references/hierarchy-paths.md，性别等标签以当前字典为准。
3. 组成只含要求变化的提案；姓名、客户、负责人等接口必填的当前值由应用读取并作为保留项。
4. 显示包含确切联系人、原值、新值和必要保留项的审批卡，等待用户确认；批准前重读有关前值，变化即停止，该检查不是原子并发锁。

**完成条件**：写完通过同一账号回读变化，并核对其他已读取资料、客户归属和负责人没有被改动；任一义务未核实即报告不确定并停止，不自动重试，不通过页面保存绕过审批。客户归属变更、负责人转移、上级或商机关联不在本目标内，请求时报告能力缺口。用户需要时可在核实后打开确切档案、切换应用提供的页签或查询联系人数量，这些页面交付仍属于完整请求，页面能力由当前应用决定。
