# 维护仓库资料

**适用目标**：建立新的 ERP 仓库档案，或把用户明确要求的变化落到既有仓库上；查询与页面定位支持该目标。

**相邻目标**：容易混淆的目标是库存数量或出入库单（仓库资料不等于库存）；设为默认仓库（会影响其他仓库的专门业务操作，当前资料工具不支持，不能用普通修改替代）；修改 ERP 客户或供应商（不同往来单位）。

**所需用户信息**：创建需要名称、排序和明确开启状态，缺少时询问，不编造默认值；可选地址、备注、负责人文本、仓储费和搬运费按用户原文提供。修改需要确切目标仓库和要改的字段新值；费用为零也是明确的新值，不能因零值而遗漏。

**利用当前事实的流程**：
1. 按确切名称定位仓库；同名时由用户选择核实的候选引用（references/disambiguation.md）。
2. 仓储费、搬运费以元为单位，见 references/erp-units.md；数量和费用来自应用，不根据说明猜测。负责人文本不授予系统权限。
3. 修改只提交明确的新值，接口必填的名称、排序和状态由应用读取并作为保留项。
4. 展示确切仓库、全部变化及必要保留项，等待新的审批；批准后重读有关前值，变化即停止。

**完成条件**：只派发一次并通过同一账号回读变化和其他已读取业务字段。完整请求中的不支持字段不能省略或改写为备注；无法核实或结果不确定时保留记录并停止，不自动重试。说明、查询和明确的表单预填不构成写入请求；核实结果后可打开仓库页面，页面操作继续遵循应用能力和许可。
