# 维护 ERP 仓库、结算账户与单据审批状态

**适用目标**：建立或修改 ERP 仓库档案（`erp_warehouse_create`/`erp_warehouse_update`）、建立或修改 ERP 结算账户档案（`erp_account_create`/`erp_account_update`），以及对已有 ERP 采购/销售/出入库/调拨/盘点/收付款单执行审批或反审批状态流转（`erp_document_status`）。

**相邻目标**：容易混淆的目标是设为默认仓库或默认结算账户（会影响其他记录的专门操作，普通资料修改不支持，但保留既有 `defaultStatus`）；新建或修改单据表头/商品明细行（`erp_document_status` 只流转审批状态）；修改 ERP 客户或供应商（见相应维护包）。

**所需用户信息**：创建仓库或结算账户需要名称、排序和明确开启状态（结算账户可选编码与备注，仓库可选地址、备注、负责人文本、仓储费与搬运费）；资料修改需要确切目标名称和要改的字段新值；单据审批/反审批需要单据类型、确切单号 `no` 和动作（`审批` 或 `反审批`）。

**利用当前事实的流程**：
1. 按确切名称定位仓库或结算账户，按确切单号定位业务单据；同名时由用户选择核实的候选引用（references/disambiguation.md）。
2. 仓储费、搬运费与单据金额以元为单位，见 references/erp-units.md。单据若已处于目标状态（如已审核再请求审批），在出卡前直接如实拒绝说明。
3. 资料修改只提交明确的新值，其余必填字段与 `defaultStatus` 由应用读取并作为保留项；若用户要求在备注（`remark`）中追加或补充内容，先读取当前 `remark` 并将“原备注；新增内容”一并提交，切勿只传新增片段覆盖原备注。单据审批会在批准卡披露连带库存或结算账户余额变动效应；`反审批` 须先在对话中向用户说明回退影响并取得明确确认，且已存在下游关联出入库/退货单或已核销收付款金额的单据无法反审批。
4. 展示确切目标、全部变化、连带效应及保留项，等待新的审批；批准后重读前值，变化即停止。

**完成条件**：只派发一次并通过同一账号回读状态或字段变化及保留字段。无法核实或结果不确定时保留记录并停止，不自动重试。说明、查询和明确的表单预填不构成写入请求；后续查询或页面交付继续完成。
