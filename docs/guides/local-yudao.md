# 芋道本地验收环境

在仓库根目录执行：

```bash
./local
```

浏览器访问 **http://localhost:48163**，使用本地合成数据账号登录。查询和导航无需重新部署服务器。

## 日常命令

| 命令 | 用途 |
|---|---|
| `./local` | 启动或更新当前 checkout 的本地环境；无变化且健康时直接复用 |
| `./local restart` | 重启本地助手；修改模型 `.env` 后也用它 |
| `./local status` | 核验基础接口、助手就绪状态、当前源码与实际 Runtime 摘要 |
| `./local check` | 只读检查工具、模型配置、缓存、页面控制器与准入策略 |
| `./local logs` | 查看本地助手最近 80 行日志 |
| `./local logs app` | 查看基础应用最近 80 行日志 |
| `./local stop` | 停止本地助手，保留基础应用及数据 |

助手源码变化会重启助手；前端输入变化时才重新构建。构建失败发生在停止旧助手之前。日常命令不重新编译芋道 JAR，不重置数据或账号，不导入快照，不执行评测题或模型验收。

这些入口直接复用产品的芋道宿主、身份校验、原生代理和页面准入，不依赖内部任务目录、测试账号文件或评测运行器。脚本不会自动打开或登录浏览器。

## 首次准备

1. 按根目录 README 准备 Python 3.12 的 `.venv` 并安装核心依赖；安装芋道适配器：`.venv/bin/python -m pip install --no-deps --editable examples/yudao`。
2. 安装 Node.js、npm、Docker Engine 和支持覆盖标签的 Docker Compose。Docker Desktop 需要处于运行状态。
3. 按[芋道构建说明](../../examples/yudao/deploy/README.md#build-and-run)准备固定缓存 `.q0-cache/yudao/`：带本仓库 Java 补丁的 JAR、管理前端 `ui/dist-prod/`、业务表结构与两个上游源码目录。管理前端构建的 `VITE_BASE_URL` 保持空值。页面控制器的准备方法见[部署指南](deploy-yudao.md#固定缓存)。
4. 在 Git 忽略的根目录 `.env` 填写 `AGENT_OPENAI_BASE_URL`、`AGENT_OPENAI_API_KEY`、`AGENT_OPENAI_MODEL`，可选 `AGENT_PROVIDER`。模型须有已登记的价格。检查仅验证配置和计价，不发起模型请求。
5. 执行 `./local check`，通过后执行 `./local`。

默认 Compose 项目为 `woa-yudao-local`。首次创建合成应用时自动生成本地数据库配置，保存到 `.q0-cache/yudao-local/application.env`；数据库按缓存中的初始化表结构建立，**不会自动补充业务示例数据**。需要演示记录时，按芋道构建说明在这个本地实例单独初始化合成数据，不连接线上站点。

本机已迁移的验收实例使用私有 `local.local.toml` 指定原 Compose 项目，保留原账号和记录。另一个 checkout 若需要复用已存在的合成实例，复制 `local.example.toml`、指定准确项目，并把该实例的原数据库配置保存在本机的 `application.env`；不要新建数据库密码。已有数据卷而配置丢失时，命令会停止并要求恢复原配置。

本机原合成账号配置保存在 `.q0-cache/yudao-local/account.json`，供人工登录时查阅；启动服务不读取它，也不自动登录账号。不要把账号文件或密码粘贴进日志和公开文档。

本地应用缓存仍只有 `.q0-cache/yudao` 一处。运行状态、会话、费用账本和日志保存在 `.q0-cache/yudao-local/`。这些文件以及 `.env`、`local.local.toml` 均不进入 Git。

## 扩充合成验收数据

需要验证分页和较长列表时，可显式运行部署目录的扩充脚本。它只接受本机回环地址、已有 MySQL 压缩备份和 `--apply`，不由 `./local` 自动触发。先在没有验收回合执行的窗口备份当前实例，再运行：

```bash
.venv/bin/python examples/yudao/deploy/seed_scale.py \
  --account .q0-cache/yudao-local/account.json \
  --backup .q0-cache/yudao/snapshots/before-scale.sql.gz \
  --report .q0-cache/yudao-local/scale-report.json --apply
```

默认每个主要实体新增 120 条具名合成记录，覆盖系统用户、岗位、部门、通知、HRM 员工、CRM 客户／联系人／线索／产品／商机／草稿合同、ERP 基础资料／采购与销售订单／已审核采购入库、WMS 商品规格、MES 客户与供应商、PMS 项目。数据包含不同日期、状态、金额和关联明细。采购入库产生应用自己的库存记录；不提交支付、邮件或外部通知。新增用户使用随机密码且不授予角色。

脚本通过应用接口新增，以完整分页中的确切键识别已有记录；失败即停止，不自动重试不确定的提交。再次执行前先核对失败步骤在应用里的状态。报告由重新读取的全量列表产生。扩充会改变全量数量、合计和排名，旧快照及其金标必须保留；后续验收使用新数据版本重新核对的金标，不能把前后结果混作同一基线。

## 显式准备跨模块演示数据

`examples/yudao/deploy/demo_data.py` 提供独立的合成演示数据准备工具，不由 `./local` 自动运行。执行前必须释放所有冻结测评占用，保存并演练恢复完整数据库备份；旧题、答案和成绩继续绑定原数据，不能移植到新数据。

工具只接受回环地址、已有MySQL压缩备份和 `--apply`。`menus` 删除三个上游外链、禁用未服务模块，并建立只读探索角色及 `demoexplorer` 账号；开发运维、接入示例和AI/支付/公众号/IM菜单不授予该角色，管理员入口保留。`broad` 经应用接口准备常用模块样本，`large --size N` 扩充指定CRM和ERP集合，最高5,000个主记录；先小批验证再逐级扩量。`personal` 使用临时的最小准备权限为探索账号建立日程、计划和汇报，结束时收回权限；`ownership` 通过应用正式转移接口设置新增客户及联系人的负责人，不能仅凭创建参数判断归属。财务凭证准备需要先在隔离合成实例中初始化科目表。参数见 `--help`；各分组名称定义在部署目录的 `demo_data_profiles.py`、`demo_data_extended.py`、`demo_data_flows.py` 和 `demo_data_coverage.py`。账号凭据只写入指定状态目录的上级 `demo-account.json`，不要提交或粘贴到日志。

按页面覆盖补数时，`broad --groups coverage-... --size 5` 可选择额外设备、仓储与质检草稿、模板和常用配置分组；这些分组通常各准备5条，签到规则固定7天。`coverage-personal --size 5` 以临时最小权限建立探索账号自己的办公申请草稿、线索、联系人、商机和合同草稿，结束时撤销授权。申请不提交审批，仓储单据不执行库存变更。页面覆盖率须固定账号和可见菜单清单，以实际页面显示记录核验；卡片/配置表单、空页、异常页和隐藏菜单分别列明，不能把辅助下拉列表的数据当成主页面有数据。管理员还保留额外运维菜单，且个人页面按当前身份显示，不能把探索账号的覆盖率推广到所有账号。

每次写入有不含请求正文的回执日志；发生未知结果或未确认派发时工具拒绝继续，须先人工核对。应用拒绝的独立分组保留失败，不能自动重试或算作成功；未提供服务或依赖未贯通的页面须单列。以应用分页读回、关联与金额核对及实际页面为验收依据，不能将预定数量或数据库行数当作可用性证据。`verify_demo_data.py` 以探索账号完整分页核对数量、关联、订单金额和借贷平衡；`verify_demo_browser.py` 在全新浏览器会话抽查六个核心列表。这些检查不证明所有菜单、完整业务闭环或模型问答已通过。新数据冻结后登记快照、版本、账号权限、数量和摘要。日常 `./deploy` 不同步数据库，服务器数据替换须独立备份、演练并核对两端业务基线，默认不复制本地凭据和会话；所有者明确授权连同账号全量替换时，账号随快照迁移，替换后仍须作废跨环境会话。

## 地址、权限和费用

对外入口固定为 `http://localhost:48163`，所有监听均绑定本机回环地址。基础应用入口为 `127.0.0.1:48161`，内部网关、启动服务与准入代理使用 `48164–48166`。同一机器一次运行一个这个端口组的验收入口；别的 checkout 占用端口时会报错，不会杀掉对方。

浏览器应始终使用 `localhost`，不要与 `127.0.0.1` 混用登录状态；访问旧 IP 的 HTML 页面会跳转到统一地址。模型按浏览器当前登录账号读取。本地宿主不启用类型化持久写入，表单只预填后交接；需要用户自己提交。模型日限额延续本地验收设置，为每账号 ¥20，费用只记录在本地状态目录。

本地入口安装仓库附带、与当前缓存逐字段核验的金额策略。启动及预检会核对发布版本、前端源码摘要和单位换算，任何不匹配都会拒绝启动；只有列入策略的接口字段可直接按页面单位做程序汇总，其它金额仍需同记录页面核对。此设置不启用云部署的金额策略。

健康检查会分别核对业务接口的成功响应、助手就绪状态、当前 checkout 和实际提供的 Runtime。网页返回 200、端口正在监听均不足以通过。健康检查不调用模型，不能证明自然语言题目的成功率；完整用户验收需要登录后逐题检查。

## 按错误处理

| 现象 | 固定下一步 |
|---|---|
| 工具、模型配置、计价或缓存缺失 | `./local check`，按明确缺项补齐，不切换到其它目录或账号 |
| 基础应用未就绪 | `./local logs app`；启动最多等五分钟，不循环重建或恢复数据库 |
| 助手暂时不可用 | `./local status`，再看 `./local logs`；更正配置后 `./local restart` |
| 源码或 Runtime 不一致 | `./local`，由入口重建必要资源并更新助手 |
| 端口被其他进程占用 | 先识别现有 checkout 和服务归属，勿直接终止未知 PID；本入口只停止自己登记的进程 |
| 登录后接口 401 | 在同一个 `localhost` 地址重新登录本地合成账号；保留具体请求状态，不把认证失败当成 503 或应用健康 |

本地助手启动最多等 45 秒。失败以非零退出码结束，保留日志；不会无限重试。重启可能中断当前回合，应在两道验收题之间执行。退出终端后助手继续运行，机器重启后再次执行 `./local` 即可。
