# 运行时行为详情

README 只保留稳定概览。本页记录影响接入、使用和运维的运行时行为与限制。设计取舍见[系统设计](../concepts/overview.md)；接入合同见[应用 Adapter 合同](../guides/integrate-an-application.md)、[Skill 与类型化操作](../concepts/skills-and-tools.md)与[持久运维](../guides/operate-durably.md)。

以上说的是已实现的路径，不是总体成功率。仓库没有规模足够的公开基准来证明它优于其它浏览器 Agent。

## 覆盖与限制

- 接口仍处于alpha，兼容策略未稳定；尚未实现跨主机扩缩容、活跃任务迁移和跨主机撤销。可信身份、委托凭据、授权映射与业务后置条件由接入应用提供。
- 浏览器操作不提供数据库事务或回滚，不确定写入需要应用读取和明确人工裁决。Odoo页面守卫不隔离外部副作用、其它浏览器会话、自定义请求中途提交或窗口关闭后客户端重试，不能当作通用写入沙箱。
- 本地源码检索可以匹配中文标签和注释，不会自动把中文问题译成英文代码标识符，跨语言召回尚未充分验证。启用托管模型时，检索到的allowlist内源码会进入模型请求，部署的数据政策须允许这一用途。
- 源码辅助的无Skill表单预填有脚本合同测试，尚无独立真实模型成功率结果，不能据此推断任意页面覆盖。浏览器与无障碍覆盖以Chromium最强，其它引擎和读屏器尚未全面验证。
- 目标式“已到达”只核对声明中的路径、控件和生效的筛选/分组，不证明所有异步加载完成或遗漏的要求已满足。模型选择的查询也未必覆盖用户意图，空读取交回Agent继续处理，不直接判定“未找到”。
- 目标式列表自由文本搜索使用限定范围读取，不输入页面搜索框；新建入口交接只高亮控件，经审核的表单预填可以填值后交接，始终不提交。
- 现有评测来自小样本参考部署，其中部分由实现者出题，不证明总体准确率。结果及限定见[Odoo评测](../../evals/odoo/README.md)和[芋道对照](../../evals/yudao/tool_loop/RESULTS.zh-CN.md)。

## 已实现能力

- 目标式回合让模型对照应用索引声明请求。索引由 Adapter 以当前用户身份编译，包含实体、字段、页面、视图、筛选、分组、页签和控件。服务端随后确定性地解析每一项声明：记录用应用自己的名称搜索，字段值用类型化读取，计数、求和与数值极值用限定范围的查询，页面用已审核路由，页签按可见名称，筛选和分组按页面自身状态，要做的修改则把对应控件高亮出来交给用户。答复由解析出的值生成，不采用模型的文字，所以回合报告的事实都是它读到的。做不到的部分如实说明；所有声明项都落实后，回合才算完成。多条记录都符合又无法区分时，回合会追问是哪一条。指名的记录不存在时，不会改成新建。条件支持数字、日期和文本上的比较；日期可以是某天、某月、某年、区间或命名时段，按用户时区计算。声明是模型输出，可能选错实体、字段或范围；这条路径会增加模型调用和耗时，不是一次调用完成的回合。
- 目标式回合可以预填表单并交接：填入用户给的值，核对各字段随后显示的内容，高亮提交按钮，但从不提交；无法确定填对的值留给用户并说明。表单预填默认关闭，需要应用安装已审核的表单端口并设置 `allow_form_prefill=True`。通过页面自身查询控件做筛选同样由应用显式开启，并且要等应用报告查询已生效才算完成。
- 挂接编译后的源码图谱时，索引可以带上部署源码里的规则（控件何时显示或禁用、字段何时必填或只读、方法在什么条件下拒绝），答复会引用准确的源码行。Adapter 还可以带上本组织经过审核的用语约定，说明某些词在这里指什么。
- 服务端 ReAct 循环在每次决策前接收工具结果与新的页面观察，并受步骤、时间、token 和模型花费上限约束。集成方可以显式开启：绑定当前 actor 的数据读取（`AgentTurnConfig.data_reads`）、由应用签发的动作效果（`action_policy`）、导航的渲染路由证明（`require_page_route`）、事先的任务声明（`require_task_contract`）。它们默认都关闭，都不授予写权限。
- 应用拥有的 Skill 使用 `SKILL.md`（YAML 元数据和 Markdown 正文），附带有界、按需加载的参考资料。目标式规划器只为已加载包的可读文本附件提供资源读取工具；正文已经加载。Skill 描述业务知识、查询、页面或写入流程；独立注册的类型化工具定义真实能力、actor scope 和效果。当前事实来自应用读取。显式启用后，可按需检索绑定部署的源码，出处留在服务端；源码检索可选且不授予权限。
- 逐步 Agent 可以在当前页面观察的有界、已脱敏证据中搜索或翻页。这不会搜索应用数据，也不能证明某项内容不存在。
- 应用无关的实体读取合同可以发现当前 actor 可读的业务实体并做有界读取，不必为每个实体写一份 Skill。另有记录引用读取，按名称或编号找候选；有歧义时返回全部候选，不替用户选。Odoo 与结构不同的合成 Contacts REST Adapter 运行同一套合同测试。
- 另有只读的 `find_page_entries`，按当前 actor 的页面和动作元数据给候选排序，只为 Adapter 审核过的独立目的地返回路由。这不代表应用的每个页面都可操作。
- 只读的 `resolve_goal_candidates` 可在一次调用中组合最多三个问答、页面或交接目标的候选检索。它不替用户选候选，也不代表目标已完成。
- 可选的应用无关当前表单合同为无 Skill 场景提供安全的标量字段预填兜底（`describe_form`、`prepare_form`、`prefill_form`）。它输入草稿、核对字段的实时值，从不点击提交控件。Odoo 的标准新建表单在离开时会自动保存，所以通用的手动提交预填在那里会被拒绝；它的类型化客户新建和编辑交接需要开启写入确认通道并取得新的审批。
- Turn 按来源职责组装上下文：当前页面是实时基线；后续追问会带上有界的对话历史；Skill 按当前任务选取；部署源码按需检索并引用，不整体注入。
- 浏览器动作会按当前观察和应用路由策略校验。页面观察只覆盖当前视口，最多暴露 200 个可操作控件。操作页面需要用户同意：每次提问中的首次页面操作（打开页面、点击、填写、选择、提交、返回、应用筛选）用一张可见卡片征得同意，同一轮后续页面操作沿用这次同意；下一次提问重新征求。工具循环式回合修订了对任务的理解后也会重新征求。读取、滚动、等待和高亮不需要征求。若用户在完整写入卡上选择了“只填到表单”，该次明确选择也准许这次表单交接所需的页面动作，不再要求第二张页面卡。页面操作许可本身不是业务写入审批：每次业务修改仍在各自的卡片上单独确认。
- `goto` 的地址已经是当前地址时，Runtime 保留当前文档并回报已在页面；目标是否已正确渲染仍由服务端的页面状态核验。跨页面跳转优先交给应用提供的 `openPage`，只有应用无法接管时才加载文档。
  芋道原生导航不会仅因当前有弹窗或抽屉就重新加载整页：页面自己的表单随旧组件卸载，布局所属弹窗保持原状；新的页面观察仍须确认目标可见、可用，弹窗未消失不算到达完成。
- 助手无法代做的页面操作，可以用 `highlight` 标出一个当前可见、具名的控件，并在不点击、不提交的情况下结束回合。这是引导式交接，不代表业务修改已经发生。
  已核验的表单预填交接不附带相关页面入口，避免离开待提交草稿。普通查询仍可附带本轮读取签发、与答案对象绑定的入口。
- 收在折叠菜单里的控件（比如记录“操作”菜单里的“删除”）在任何应用里用同一个办法找到：目标式回合最多展开三个页面自己声明为折叠的菜单，标出控件，并在答复里说明它在哪个菜单里。不会选中菜单里的任何一项。
- 当请求指向一个页面状态（打开某个界面、切换页签、应用筛选或分组、到达某条记录）时，Agent 先用 `set_target` 声明这个状态，服务端把每次新的观察与声明比对后才报告到达。声明目标不授予任何权限。用户读到的那句话由观察到的页面生成，不采用模型的文字。
- 通用点击作为动作可以保持禁用，同时由应用通过可选的点击策略放开其中一部分。Odoo 参考集成放开页签、主页按钮、指向已审核页面和记录的链接，以及这些页面上具名的视图切换、翻页、搜索和菜单控件。工作流按钮、新建、操作、行选择、行内编辑和未审核页面仍被拒绝。
- 声明了页面只读守卫的集成，可以在当前观察中提供最多 32 个由应用列出的筛选与分组选项；可选的 `apply_facet` 工具应用其中一个，并以新观察到的生效状态为准。
- 应用可以声明 `page_write_guard` 路径，在 Agent 操作页面期间把已登录会话变成只读。Odoo 的 `woa_runtime` 1.5 实现了它：窗口开启期间，该会话的每个请求都在只读事务中执行。请先部署 1.5 版 addon，再部署这个 Adapter。
  只读取页面投影的 `observe` 不开启或续期写保护窗口；其它浏览器动作仍须通过已声明的窗口检查。数据工具之后无法取得新页面观察时，以 `page_observation_failed` 结束、记录回执错误代码并提示刷新后重新发起，不自动重试写入。
- 已注册的类型化读取不要求匹配 Skill。包可以在 `agents/woa.toml` 中声明经过审核的实体和页面身份，用于选择知识，不依赖写工具安装。集成可要求写入绑定显式加载的 Skill 及其操作清单。清单只限制提案，不安装工具或授予权限。工具 schema 按部署的写入开关和当前 actor 的权限范围过滤，派发时再次校验。
- 开启业务写入并安装带效果合同的 Skill 后，普通目标可在变更、拒绝或仅源码出口前征询执行一次。未要求执行或没有匹配操作时，提案可在批准前让渡回普通路径。范围声明无效后，让渡在未启用源码时继续原有完整索引恢复；启用源码的部署保留范围依赖拒绝。普通查询/页面保持原流程；仅源码请求可能多一次选择调用。写关闭时使用普通解释器，并可加载 Skill 知识。该准入机制已有合成合同检查，不能据此认定真实模型成功率。已实测的 Token Plan DeepSeek 端点使用供应商 `auto` 编码要求工具声明，客户端仍拒绝没有工具调用的响应。
- 只有用户的请求本身能要求写入。Skill 任务声明从完整请求解释执行意图，范围提示或工具可用性不能证明该意图。解释仍可能出错，包括否定请求。记录和页面文字不授予权限，每项写入仍需完整可见审批卡片。
- 批准协议可在单张写入卡上显式提供“只填到表单”的第三种结果；未提供该选项的写入卡和页面操作卡会拒绝这项决策，重复或冲突的决策仍按同一批准编号处理。面板只有收到选项才展示按钮，保存和预填都要求卡片达到相同的可见性门槛。服务端仅在应用适配器能把准备好的确切提案映射到当前 actor 的暂存表单时提供选项，绑定提案摘要、操作上下文、目标页和字段值。选择预填会消费该卡并授权本次交接所需的页面动作，仍经过应用页面动作准入和实时回执核验；本轮撤下写入工具，不取得业务写入授权，也不派发业务写入。核验失败则停止，不自动重试或声称表单已经填好。Contacts REST/普通 HTML 测试应用已通过真实浏览器的“新建联系人”交接检查；芋道原生写操作尚未声明可转换范围，实际写入卡仍只有保存/取消。
- 写入默认关闭。核心 turn 配置默认关闭所有可能触发应用写入的浏览器动作（包括导航），Adapter 必须显式开启自己审核过的子集。开启的写入把准确的效果和对象绑定到一次性的新审批上，最多派发一次，并通过应用核验结果。超时或结果不确定的写入记为 `indeterminate`，不会自动重试。
- 芋道模型回合从部署版本的菜单与已知记录路由生成地址清单；菜单存在只证明该地址属于当前账号的目录。页面准入分级：导航、查询、分页、页签对当前账号的菜单页和记录详情路由默认放行；打开表单、填写和加行仍须在部署策略中逐路由声明处理器条目。页面初次加载也可能在导航动作结束后异步调用会写入的 GET，因此发布扫描逐页访问菜单页并执行查询、重置、翻页和页签、打开表单，把观察到写入的路由和没有任何源码与数据表的路由写入排除名单；排除名单优先于两级放行。服务端的动作准入、应用只读窗口与方法围栏逐次判断。查询行的下载、导入、删除及提交类控件被拒；暂存表单只允许预填和交接。查询重置须有新一版应用列表读取，且可见查询控件的值与这次读取的参数摘要一致；浏览器对空文本框省略 `value` 属性时按空值核对，未显示字段若变化则不确认。页面观察为每个可见表格行提供有界的“列名=值”；`call_api` 可附同账号实体索引绑定的部署列表列名和应用字典，详情读取只沿用同一实体的定义；未知接口或有冲突的绑定不套用其它实体。空结果也可附合法代码的含义，避免把通用状态码套到业务审核状态；只读接口发现还可附带同一原生搜索表单的固定选项及当前账号字典名称，只有接口已发布的查询参数会展示；无源码、动态选项或绑定冲突时保持缺省，不猜测状态代码，也不据此新增参数或权限。这些元数据不证明页面已经打开，实时页面观察优先。对应列表接口与当前页面的读取路径一致时，另附本页列名。负责范围列表中的空结果不证明详情无权限；查找会继续读其它实体，确切详情权限以同 actor 的详情 GET 为准。
  部署可重复传入`--native-page-disable`，取值为`query`、`paging`、`fields`或`lines`，关闭相应页面处理器，Python配置为不可变集合`native_page_disabled_handlers`，默认不额外关闭。关闭优先于菜单和逐路由许可，同时影响能力声明、工具参数与实际准入；页面筛选/分页关闭不影响同账号API条件问答和程序汇总。`fields`与`lines`同时关闭时，已审核表单入口仍可打开供用户手动填写，助手不预填。另可使用`--no-native-edit-prefill`（Python配置`native_edit_prefill=False`）仅保留有实时新建模式证明的预填；默认通用宿主保留编辑预填，本地验收入口显式关闭。页面控制器可通过既有`readElementPageControl`提供`kind:form`、`mode:create|update`和原生`recordId`（新建为null）；Runtime从实时控件取得并将模式/编号纳入新鲜性指纹，不接受页面摘要中的同名文字。芋道依据当前挂载的原生表单模型及实际新增/编辑标题取事实；嵌套明细表单以唯一主表单的记录状态为准；多个独立主表单、模式未知、编号矛盾或填写过程中改变时拒绝预填。服务端逐步核对同一表单实例，新建保持可用；编辑表单仍可打开，建议值由用户手工填写，不依赖请求中的动词判断模式。
- 芋道列表页的原生页签按分级准入在菜单页上默认放行。当前账号的菜单页、已渲染列表和成功应用的列表读取都成立时，才能点击页签；核验要求同一页签实际选中，且同一列表接口以不同查询参数成功重新读取。记录详情页的页签仍核对当前记录和实际选中状态。
- 芋道部署可选装逐字段核验的金额策略。策略把只读接口字段、页面路由、前端组件及金额格式器的源码摘要绑定到一个发布版本；宿主启动时核对源码、页面接口映射和编译出的显示换算因子，不一致即拒绝启动。只有策略列出的字段，`call_api` 才把接口原值转换为页面显示数值、标明单位，并允许纯查询直接使用；其它金额字段仍须在同一记录、同一列的页面上核对。单价可保留“元/天/KG”这类复合单位；必须额外提供`unit_source`的组件与SHA256，启动时从该组件同一字段的字面单位声明核验，不能默认为元。附带的策略记录隔离合成实例中取得非零同记录样本的14个开发候选；云部署默认不启用，须在该部署按同账号逐字段核验后显式安装。
- 芋道原生写入把应用返回的错误类别和代码脱敏记录为对账证据。已有确切目标 ID 的更新或状态变更，错误响应后可以用同 actor 回读证明完整效果；没有完整证明时仍为 `indeterminate`，不会据一次未查到效果的读取改判失败。复合跟进可能在应用报错前已经插入记录，故没有可归属的确认 ID 时保持不确定。
- 短期 actor/tenant/workspace 主体可绑定浏览器 capability、工具 scope、审批、mutation、审计记录和撤销状态。
- React 助手面板只是服务端状态的视图。启动按钮从脚本运行起就在页面上。用户发送消息或重新打开对话时建立会话，空闲五分钟后释放；失效的会话在下一条消息时恢复；新文档首次握手发现会话已关闭，且本地没有未决任务、动作、批准或待回传结果时，可向已配置的启动端点重新获取一次会话并恢复历史。这条恢复路径不重发消息或页面操作，持有未决状态的文档不使用它；无法恢复的启动失败会在面板里说明并提供重试。打开面板时会恢复当前用户在服务端的历史。
- 最终答复保留 Markdown，面板以封闭语法显示标题、强调、列表、表格、引用和代码；HTML 与图片不执行或加载，链接仍受当前会话的允许来源约束。芋道提示模型按结果选择简短句子、列表或表格；具体排版仍取决于模型输出。
  模型循环中的普通中间文字不向用户交付，直接答复须把完整正文放入 `finish.answer`，不能引用未发送的“上一条答复”。没有工具调用的中间输出会被明确反馈为未交付，并从后续决策历史中以未交付标记替代；原始模型返回仍按原有脱敏轨迹保留。两次协议纠正后仍未调用工具时以未完成结束，不把未经核验的中间文字兜底成答复。普通中间输出的协议纠正不额外启动办理完成复核。
  关闭业务写入的部署不做任何模型复核：写入意图、页面工具或填写过的值都不再启动完整请求复核，程序检查只纠正或补足答复，不以拒绝结束回合。页面步骤因部署未开放、账号无权限或目标未通过核对而没有执行时，服务端在答复后列出这些未执行的页面操作。同一只读工具以完全相同的参数失败后，相同调用不再执行，工具结果说明原因；第三次相同调用时服务端结束回合并交付本轮已读到的结果。启用业务写入的部署保留应用或页面工具要求的完整请求复核：最多纠正一次，复核不可用或仍有争议时不报告完成；该复核由模型判断，不是确定性证明。
- 应用只读过程可显式提供 `StructuredQueryAnswer` 作为列表正文，公共模型循环为它签发仅本轮有效的 `finish.read_answer` 引用。模型先收到读取结果，再选择引用结束；列表字段值由服务端排版，不采用模型重写的值。已经请求这类交付后，`done` 必须选择一份完整结果且 `answer` 为空；缺引用、跨回合引用、来源不完整、最终预算装不下全部记录时不接受完成，可用 `cannot` 说明未完成部分。每轮只保留最近四份候选，引用不授予新的读取、页面或写入权限。适配器可在`StructuredQueryAnswer.actor_digest`与`record_ids`同时提供原生账号绑定和逐行编号；编号须唯一、不可变并与正文行一一对应，结束时复核账号，元数据不改变可见正文。不提供这组证明的旧调用仍可交付文本，但不具备原生记录身份保证。结构化投影最多5000行、20列、字段键限字母数字下划线，每值1000字符、全部值合计100000字符；原有工具的读取上限不因投影上限改变。最终文本预算仍逐轮生效，超出时不静默截成“完整名单”。该合同已在芋道分页API和Contacts REST测试应用中验证；查询接口、筛选条件和交付字段仍由模型选择，程序不据此证明它们符合完整用户意图。
  芋道模型工具以 `call_api(summary={...})` 请求程序交付：`columns`选择实际列，`where`声明条件，`order_by`声明完整名单排序，分组和统计沿同一接口。模型用 `finish.read_answer`交付保存的正文，不重写数值或字典解释；普通自由文字答复仍不具备相同保证。旧Python调用的`deliver=true, fields=[...]`仅转换为`summary.columns`；与`summary`同用时以显式`summary`为准，模型工具不再展示两套交付参数。字段类型仍经过原核验；已审核金额按显示单位换算，未审核金额保留接口原值并标“单位未核验”，不换算、不加单位。工具报告字段、条件、数量和完整性；同名记录保留多行，多次分页读取不构成同一时点快照。
- 程序汇总列可附应用提供的`display_name`和不可变代码字典`labels`，只用于表头、条件和结果的排版；原始数值类型、比较、排序、分组身份及计算结果不变。已声明字典中没有该非空代码时，正文保留原代码并说明字典无此代码；没有字典声明的普通字段不作此推断，null/空串仍为缺值。合计/计数不会被当作代码标签，最小/最大值保留原字段标签。名称和标签也受既有交付字符预算约束。
- 应用可把同一账号已读全的有界集合交给通用程序汇总：模型只声明条件、分组、计数/去重计数/合计/极值与排名，行、列类型、单位、实际查询范围和完整性均由适配器提供。计算采用十进制，不执行表达式；文本不改空格或大小写，日期有明确类型，时间阈值须带时区。`between`包含两个端点；自然月等时间段使用大于等于起点、小于下一时间段起点，保留末秒的小数精度。关联对象按编号分组，展示名称相同也不合并。缺失字段、空值、空串与数值0分别处理；空集合的合计为0，非空集合全无有效数值的合计为空并说明原因。排名按第N个位置保留全部临界并列，不自动取N种不同数值。
  芋道`call_api(summary=...)`与Contacts REST使用相同合同。芋道从汇总声明自动选取所引用列，无须在`fields`重复声明；列须在当前接口已发布schema内，合计最多12列。`summary`要求`row_offset`为0；旧`deliver`兼容调用的转换不改变此限制。`summary`包含`where`（AND条件）、`group_by`（最多2列）、`measures`（`op`、`column`、`as`）、`columns`和`top`（measure别名、1–50名、升降序）。无分组时统计整个命中集合；逐记录排名须按记录编号分组。完整记录排序使用`columns`与`order_by`（最多3列，`direction`为`asc/desc`，`nulls`为`first/last`、默认在后），不与`group_by/measures/top`组合，不设置隐含条数上限。排序键可来自未展示的已发布列；已知空值保留、同值保留读取顺序、未读到的排序值拒绝排序。全部行仍受5000行、结果与正文预算约束，不能把前50条冒称完整名单。服务端读取交付使用配置的正文预算，模型自行撰写的`finish.answer`仍受工具文本上限限制；芋道读取正文预算沿用服务端面板合同的20000字符，超出时拒绝完整交付，不静默截断。原生关联编号与名称在同一行返回且schema均已发布时，可附带名称展示，分组身份仍为编号；同一编号名称矛盾则拒绝交付。部门列表的负责人编号经同账号读取的用户精简列表显示昵称，列标题为“负责人”，只作展示。已逐字段审核的金额用原值和审核系数构造精确显示数值，不推定币种或新增取整规则，也不支持跨单位换算；未审核的金额列保留原值，表头中标“单位未核验”。
  汇总声明的等价写法由程序改写并在工具结果里说明，不改变所选记录或计算：`==`、`<>`、`ge`等运算符按对应运算符理解；不是英文标识符的统计别名改为 `m1` 等。`count` 可带列：列为记录编号 `id` 时按记录数计，其它列计其非空值。条件里数值列的数字字符串、关联编号的整数、文本列的整数和布尔列的 `"true"/"false"` 按列类型视为同一值；其它类型不符仍然拒绝。
  汇总结果按本轮read_answer交付，结束时核对账号。未读全、重复记录ID、类型未证实、缺字段或交付预算不足不能报完成；结果保留来源、实际条件、命中数量、缺值和并列说明。一次引用覆盖一份集合中的多项统计；它不自动完成其它页面、跨集合或解释义务，不能表达完整请求时须说明尚未完成。普通`fields`的历史自动统计暂保留作读取反馈；新增需筛选/排名的最终统计使用显式`summary`，不把两条路径的数字拼成一份结果。该合同测试证明指定输入下的计算与交付，不证明模型选对了用户要的实体、范围或条件。
  单记录字段可通过`summary.columns`或普通`fields`读取原生详情GET实际返回的列，由程序交付或模型按本轮读取作答；仍读取原详情接口，不改成新的搜索路线。详情必须有原生记录编号，带`id`请求时返回编号须一致，缺字段照常拒绝。单记录投影同时保留该编号，便于核对答案对象。
- 模型回合的只读工具可附带应用签发的页面或记录目标。服务端只把已完成读取中、名称出现在最终答复里的唯一目标作为独立链接数据投影到结果下方；同名的多个记录、跨域地址、带查询参数或片段的地址、未完成或写入回合都不附链接。芋道用当前账号的菜单读取签发唯一页面目标，用同账号详情读回签发唯一记录目标；Contacts 测试应用用当前账号的页面目录及二次联系人读取签发列表页和记录目标。链接由用户点击，浏览器只在本地检查可见表单、对话框和未保存输入：确认无草稿且应用提供 `openPage` 时走应用路由；否则在新标签页打开。应用路由拒绝时，已预留的新标签页承接目标地址。浏览器不把草稿状态送往服务端。
- 新对话的示例由应用提供，点击只填入草稿。翻阅或加载较早的对话记录时，面板保持当前阅读位置，并支持返回最新消息。
- 一个会话可以同时在多个页面上打开。所有页面看到同一段对话；回合在发起它的页面上运行，只有那个页面会收到页面指令。已有任务进行时，新建会话会提示等待并保留当前历史；服务器接受后才清空本页视图。旁观页面收到回合结束事件时，不关闭执行页面的写保护窗口。
- 同一标签页刷新或跳转后保留助手展开或收起的选择；保持展开时自动恢复当前账号的服务端历史。确认卡片仍有时限，超时后撤下不可操作的卡片、恢复输入，并在结果中保留超时和重新发起的说明；过期审批不延用。
- 面板支持浮层和抽屉，所选形态与窗口位置保存在当前浏览器。抽屉可能收窄宿主页面；应用按视口定位的弹窗可能被助手遮挡，接入时需要验证。
- 可选 SQLite 存储提供 session 所有权、进度 outbox、有界会话上下文、mutation journal、备份和明确的人工结算。

芋道的数据汇总会将已编译、可证明为返回行同字段直接等值的编号条件再次应用于读取行，避免接口忽略关联参数后扩大范围；无法证明的参数不猜测。指定关联对象时，助手应先解析当前账号可见的唯一编号，以精确条件限定汇总，并且不得加入用户或已审核约定未要求的筛选。

## 执行器与集成细节

模型驱动循环中，即使点击页签的初始回执仍在加载，也可根据应用核验通过后的稳定观察结束。表单交接核验通过且仍对应当前页面时，服务端明确提醒用户核对后手动提交；交接失败或仍需补充信息时不报告交接完成。源码工具用于用户明确提出的实现问题；当前业务值和配置需要从应用读取，不能以源码默认值代替。工具选择仍取决于模型。

芋道提示词按交付区分“查看”：查看某条记录、详情或页面时进入对应位置；查看字段、数量、金额或有哪些记录时直接回答数据，同时要求数据和页面则分别完成。金额仍受下文的逐字段显示单位核验限制。这是模型的解释规则，不能保证每种表达都会正确分流。

芋道`find_record`只按名称查找；名称查空不证明原生ID或业务编号不存在，编号查询使用应用已发布接口的对应参数。预填续轮沿用同一有界会话中用户指定的字段；当前请求明确收窄字段时不从历史扩充，新会话不继承。字段标签的单位装饰可在名称唯一时省略；字典枚举的括号排版可按当前账号的唯一原生选项解析，关联记录名仍须精确匹配。部分字段已填写而后续动作无法核验时，提示指出停止的字段与已执行步骤，不自动重发；当前草稿由用户核对。

芋道原生宿主只使用 `slim`，由应用无关的 `ModelDrivenTurnExecutor` 驱动。启动必须提供版本匹配的 v2 方法围栏、带审核路由和处理器的 `--native-page-policy`；live forms 和应用自己的只读窗口始终启用。缺少或不兼容的配置在模型和网络启动前拒绝，不自动回退。旧 `goal`、`page-agent` 的宿主选项已删除，传入会由参数解析拒绝。写入仍默认关闭，浏览器提交始终关闭。助手打开页面时，由应用自己的 Vue Router 在用户所在的文档里打开，页面重新构建、路由历史保持完整，所以助手窗口不会收起，应用也不用重新启动；应用无法接管的地址才按整页加载；地址与当前相同时保留文档。slim 回合保留目标式回合的协议（身份、本轮页面操作同意、写入观察、回执和预算），由模型从一小组固定工具里逐步选择下一步——当前账号自己的菜单、以当前账号身份调用的应用只读接口，以及 Runtime 的点击、填写、选择、滚动、跳转和高亮。它只在方法围栏加应用自己的只读窗口下启动，从不按提交控件；方法围栏会拒绝的 GET，它的接口工具也不会调用。不带 `--native-writes` 时它不做任何写入。带上之后，同一段对话可以加载已安装的 Skill（`load_skill`）并提出该 Skill 的类型化操作，操作在加载后成为带已安装输入 schema 的工具。每个提案都走共享的写服务：以当前账号做只读准备，已登记的字面输入与用户本人的话逐字比对，应用对所准备效果的投影与提案输入比对，一次完整可见的批准，一次派发，同账号回读。在征求用户批准之前被拒绝的提案回到同一段对话，可在有限次数内修正；被拒绝批准、被应用拒绝或结果不确定的写入结束本回合，不再重发。目标式执行器的 Skill 选择、单提案和让渡步骤不在这个回合里使用。跨回合它只保留宿主的有界会话状态：用户的原话、每回合的答复和该回合已核对的写入，默认最近四回合、32 KiB，按会话标识持久化；所以宿主重启之后对话可以接着进行，此前回合读到的数据和看到的页面要重新读取。接口读取和按名称找记录的结果在告诉模型之前先隐去凭据：本适配器从不读取的字段（密码、密钥、令牌、渠道配置）、名称表明是凭据的配置项的值，以及任何字符串里的凭据或会话参数赋值；其中的行、值和名称作为应用数据围起来，模型被告知只把它们当事实读、不当指令执行。当前登录用户在应用里本来就能读到的业务字段不做遮蔽。回合进行中，面板时间线在页面动作之间说明它在做什么：在查找哪个页面、数据来源或记录，正在读取业务数据以及读回了哪个列表的多少条，正在准备一次更改，正在核对结果；这些句子由服务端给出。宿主在用户的会话建立时默认于后台读好该用户的菜单、建好该用户的应用索引，让这些读取与回合开始前的等待重叠。它只预热菜单/API 说明和 outline，不预读明细表详情。读取量取决于安装的模块。冷启动测量由测试配置关闭预热，生产 CLI 不提供预热开关；预热结果不能代表冷启动性能。目前只在小规模合成评测集上运行过。

芋道宿主建立或续期会话时，会先用页面提交的访问令牌向应用核实身份，再读取组装可选写入工具所需的字典。身份读取或随后的字典读取返回 401 时，bootstrap 保留 401，页面 loader 用应用的刷新令牌续期并重试一次；应用返回 403 时保留权限拒绝。上游读取故障仍是 503，不会触发令牌刷新。身份未核实前不建立新会话，也不派发业务操作。
芋道原生 API 经过页面代理时，身份失效的请求在代理处拒绝且不派发，响应采用应用自己的 HTTP 200、`code=401` 格式，让现有前端续期访问令牌；页面批准接口仍用 HTTP 401 拒绝无效身份。续期是否成功由应用的刷新令牌决定。

当前页曾有失败读取而处于 `blocked` 时，模型仍可请求离开该页：只有同源、且属于当前账号菜单页或记录详情路由、不在部署排除名单的确切目标可进入跳转准入；`pending` 状态、当前页控件操作和被排除的目标仍被拒绝。跳转成功仍须由目标页的就绪状态与应用渲染路由证明核验，地址变化本身不算完成。`invalid_target` 只说明当前页状态或目标地址未通过校验，不能据此断定目标不受支持或账号无权限。

芋道的 `call_api` 以当前账号身份调用已发布的只读接口，保留应用查询参数的原义，不自动添加或替换负责范围。CRM 不带 `sceneType` 时读取应用普通列表；指定“我负责的、我参与的、下属负责的”时使用对应参数。普通列表可读字段不证明该记录的详情访问权或编辑资格，后两者仍由应用独立核对。页面筛选以当前页签或视图为范围，筛选成功但返回空列表时如实交回当前范围结果，不自动跨范围查询或把空结果说成记录不存在。

带 `fields` 的分页读取从所请求页起最多跟读 5,000 行。只有从第一页开始、分页总数有效且稳定、跨页记录 ID 不重复、实际读到总数时，才计算全量数值合计与极值、日期列的每月行数，以及类型和状态列的分组与合计。其它情况明确报告未读完，不提供这些全量统计；应用声明的 `total` 和本次读取行数分别说明。`complete=true` 只表示分页校验通过，不表示读到了同一时点快照；多次分页仍可能混合不同时点的数据。

工具返回给模型的行有展示上限，读全不等于完整名单已经展示。较大投影用明确列顺序的 JSON 数组减少重复字段；有后续行时返回 `next_row_offset`，模型可保持路径、查询参数和 `fields` 不变，以 `row_offset` 续读展示窗口。该参数不会发给应用，也不会改变统计范围；每次仍重新读取应用，没有跨窗口快照，模型上下文和回合预算也仍有上限。只有全部所需窗口都被读取并保留时才能声称完整列出；不能靠猜名称条件补读或把部分行当完整名单。 模型循环的 `finish.answer` 长度按服务端实际交付预算声明，不能先接受更长答案再静默截短。芋道原生宿主为较长名单提供最多8,000字符的交付空间和8,192输出tokens的单次模型预算；回合总预算保持不变。工具与阶段合并参数见[执行器](../concepts/executors.md)，部署参数见[芋道部署说明](../../examples/yudao/deploy/README.md)。

按名称定位 CRM 客户的记录查找仍会在三个负责范围未命中时，用同账号普通列表补充候选并核对详情权限。普通接口读取则直接返回应用本次获准的列表字段，不为了判断列表可读字段而额外要求详情可读；详情拒绝也不抹去同账号列表已经返回的字段。

完整读取后的分类统计按字段原值计数；关联对象应按编号分组，名称只用于展示，同名不同编号不能合并，缺值行单列。最多完整展示 32 组；超过时展示覆盖前三名的分组及临界并列，仍以 32 组为限。临界并列超过展示上限时明确给出未展示的并列组数，不能据此宣称已列出完整前三名名单。未读完时不提供这些全量分组统计。

芋道 `call_api` 带 `fields` 读取列表后，工具反馈先说明本次查询是否带业务筛选；未筛选的全表合计和分组不应被当成用户点名子集的结果。部署可选装从同版本服务端源码编译的筛选语义策略（`--native-filter-semantics`）：`search_api` 的接口行为每个已解析的查询参数标注其条件语义（包含匹配、等于、区间等），带业务筛选的读取在范围行后为每个已提交且已解析的条件标注同一语义；解析不出的参数不标注，标注不扣留数据也不拒绝读取。完整读取的列表即使只含一种分类也会给出该类的行数；数值列还给出覆盖前三名的降序档位和并列行数，跨过名次的并列行不会被截成唯一名次。未读完时不输出这些全量结果。模型指令要求把名称、前缀等条件落实到已发布的筛选参数，或用显式`summary.where`在读全后按条件计算；对实际触发结束验收的回合，验收提示也要求检查读取范围。工具按本次实际参数返回结果及其范围，模型仍须核对这些条件是否覆盖用户请求；纯查询回合通常不触发结束验收，仍须按题目核验答复。服务端审计记录已安装接口路径、查询参数名、页码和页大小、已发布的选取字段名、实际读取行数、声明总数与是否读全；筛选值和记录内容不写入审计。审计能复核调用路线及读取范围，不能单独证明模型选择的筛选条件符合用户意图。

芋道宿主默认在每段会话的运行目录（`<state-dir>/runs/<会话>/`，与审计同目录）为每个回合写一份回合记录 `turns/<序号>.json`：模型每次请求收到的消息（同一条消息只存一次）、提供的工具名和模型答复，以及本回合的用户原话、起始路由、账号摘要、终态、耗时和答复。只记录提供方已接受的请求，因此只含已通过出口检查的内容；写入前整份记录再做一次凭据形式检查，发现时只保留终态和耗时。答复引用了服务端读取结果时，私有回合记录另保留最多四份`server_deliveries`：本轮引用、来源/计算投影、由应用读取回执提供的实际来源引用（若有）、实际排版正文及是否完整交付。来源引用与被引用的结果绑定，不取最后一次读取，也不接受模型填写。记录后终态仍可能变化，消费方必须再绑定最终答复与终态；这些业务值不进入普通审计，也不作为模型上下文。与审计不同，回合记录含模型看到或服务端交付的业务数据。文件权限 0600；宿主按 `--turn-trace-days`（默认 14 天，0 为不写）在启动时和之后每小时最多一次删除过期记录。


公共模型循环允许应用为已拒绝的页面过程提供有界、服务端生成的终止说明，保留具体字段问题与未完成范围；该说明仅用于 `agent_refused` 的失败页面结果，不改变派发状态，不覆盖权限、传输或不确定写入结果，也不会触发重试。

公共模型循环校验闭合的工具 schema，把类型化结果和新鲜页面观察交给同一个 Agent，并使用应用签发、一次消费的动作或暂存步骤授权。芋道负责菜单/API 知识及日期、分页、明细过程；结构不同的合成 Contacts REST/HTML 应用验证同一核心。最后一次页签点击可以附带答复，只在确切动作经过保护与应用核验、同一标识的页签实际选中后结束。芋道也可在一批分页要求的页码、每页条数全部符合应用当前列表回读，并绑定本次确切核验命令后直接结束。名称查找给出唯一命中已读到的编号；全局未命中明确索引的覆盖边界并附相关已发布接口元数据，元数据不证明记录存在或不存在。普通模型结束标为 `not_claimed`：局部动作回读不独立证明整个请求或模型答案正确。配置部署源码时，同一循环提供 allowlist 源码检索、有界行读取和可选 Git 历史。芋道宿主的用户态源码工具默认关闭：`--source-root` 绑定的版本仍会在启动时校验，构建期扫描经各自的 CLI 直接读版本树；只有显式加 `--runtime-source` 才向模型提供上述源码读取。关闭时回合提示词要求实现类问题用固定答复说明本部署不提供源码说明，不凭记忆或猜测描述实现。源码结论必须引用本轮证据和原文支持，答复由服务端标明绑定的源码版本；纯源码回合检索后仍找不到直接依据并选择拒答时，服务端固定说明已查的来源和结论边界，不采用模型自写的拒答内容。这些检查证明引用归属，不证明语义正确。纯源码回合无需浏览器观察或业务元数据；调用应用工具前必须绑定请求页的真实观察。普通操作不要求源码仓库。完成（`done`）答复结束前，应用可对答复数值提供一次可追溯读数（芋道提供该读数）：答复里的金额、数量、百分比须在本回合已提供的起始页面、工具结果或用户原话里出现，比对前统一千分位、小数尾零和正负号；字母数字混合的单号、产品编码等另按完整标识逐字比对，不归一化大小写、前导零或分隔符，不接受前缀/后缀片段；日期、时间、纯数字记录编号、电话和地址不参与该抽取。找不到来源时，程序把清单交回同一模型一次，请它改用读到的值；编号须逐字保留，其它数值可以说明计算依据或无法核实；第二次答复照常结束，不再循环。审计记录 `untraced_numbers` 事件（数值清单及是否交回）。这是反馈而不是闸门：不扣留已读到的数据，不提前结束回合；`need_input` 与 `cannot` 的答复不做该检查。


芋道查询下拉绑定当前页面的选项标签和原生标量值，再核验成功生效的查询。原生日期范围选择只在输入框所拥有的弹窗内定位确切日期；目标月份不在当前两个月面板时，通过该弹窗的上个月或下个月按钮有界移动，再核对目标日期，无法核对时拒绝该页面动作。只有明确审核过的查询表单展开按钮可显示更多字段。类型化数据权限拒绝会结束回合；接口结构纠正只报已安装字段，不回显被拒绝的输入。

系统用户页的部门树按已审核的 `deptId` 查询处理。观察只提供当前视口内、确属当前页面原生部门选择器的节点及其自身点击区域；同名节点附层级路径。点击后须看到该节点的选中状态与新一版成功列表读取一致，并核对部门参数、其它筛选、页码和每页条数。重复点击已选节点会取消部门筛选。树上方的部门名称输入框只搜索树节点，不作为用户列表的筛选字段开放。

记录详情中的页签选中只证明本次点击生效。芋道还用同账号详情读取核对当前记录：用户明确给出该编号，或给出经同账号名称搜索证实唯一的记录名时，才可沿用直接结束；没有这项绑定时，启用业务写入的部署要求公共循环用已有复核器对照完整请求与当前页面；关闭业务写入的部署不做模型复核。复核有疑点时交回同一 Agent 一次纠正，最多复核两次；复核不可用或纠正后仍有疑点时说明页面状态尚未核实，不报告完成。此路径会增加模型调用；语义复核本身仍可能判断错误，不构成任意自然语言目标的确定性证明。

芋道 slim 对明确只问业务状态、且没有页面操作、金额核对或修改要求的提问，只提供当前账号的只读查找与接口工具；模型即使提出页面动作也会被拒绝。带有页面或金额要求的混合请求仍使用原有工具与核验。

slim 的记录导航使用当前账号的实体/页面 outline，在动作前后精确读取目标详情，不编译无关的内嵌明细元数据。暂存表单选择时，slim 直接调用 Runtime 在同一归属列表内的有界选择：由它展开列表、精确查找标签，拒绝有歧义或禁用的选项。标签不存在时，交回该列表有界、脱敏的标签，不自动替换名称。新增草稿中类型已明确的关联字段，提示模型先尝试用户给的名称，再依据本字段选项纠正；本地选项不足时才补充范围明确的读取。筛选字段须先出现在当前观察中，折叠字段先展开再填写。下拉展开后输入框没有唯一的当前控制器序号时跳过收起，仍须核验草稿未变及表单身份。只有 Runtime 证明未选中选项且本地草稿未变，再由应用的可选证明确认同一表单和账号时，才允许纠正；其它已发出但核验失败的草稿动作结束回合。审核过的表单入口可以与导航合并（`goto(open=...)`）。按字段名填写可带 `then_highlight` 和 `answer`：每次输入仍逐个准入、核验，之后服务端回读用户给出的字段及此前观察到的未填写字段，再由既有 Runtime 表单交接核验所填字段的实时值并标出提交按钮。同一批填写可以先通过精确命名的已审核按钮新增 1–4 行（`add_lines`）；每次建行必须保留同一表单及此前字段值。无标签的明细控件按当前精确 ref 和实时表单实例核验。已审核的 ERP 销售订单和其它入库表单，产品自动带出的单价由同一账号精确读取产品后核对；其它未填写值仍须保持原样。完整的筛选批次可带 `then_click` 和 `answer`，仅凭本工具真实且经应用核验的生效查询回执结束。字段缺失或填写失败时不会点击搜索。不完整、被替换或屏幕外的字段需要继续观察。浏览器提交和写入审批规则不变。客户详情导航从当前账号的实时应用权限行反馈编辑资格，不由编辑控件是否可见推断。CRM 客户名称在当前账号各业务范围未命中时，用应用普通名称列表判断是否为范围外记录；仅客户的这项已审核范围语义允许返回类型化权限拒绝。CRM 联系人的范围查询会与同账号普通联系人列表的同名候选合并去重，避免范围内外同名时误判为唯一；普通列表新增的候选还须经精确详情 GET 验证身份与访问权，失败时保留应用返回的拒绝，不据列表可见性推断无权打开。slim 调用某个芋道只读接口被应用明确拒绝时，拒绝只归于该接口，不终止整轮，也不据此宣称其它已公布接口或整个用户目标无权限；助手可继续使用当前账号获准的读取路径。未审核或被校验拒绝的页面动作同样只作用于该次动作；两类拒绝的反馈都写明已读到的结果不受影响，模型据此在已读结果能回答用户问题时照常作答，“无权限”“读不到”的结论只能来自指向该记录或数据本身的确切读取被拒（提示词有同一条原则）。身份失效、页面动作拒绝和写入拒绝仍按各自原有边界处理。名称查找的可选列表预览只传入接口声明的参数，需要额外输入的接口跳过预览。按列投影的 API 结果会列出已返回、有文档但未展示的列，供模型补读。动作拒绝和回执保留明确错误码与派发状态，审计记录脱敏；后续等待不覆盖已确定的动作结果。每次读取仍由应用认证和授权；凭据失效或变化时拒绝继续执行。表单和写入准入仍须核对当前权限。

芋道原生新增/编辑表单的日期精度来自当前挂载控件的类型，并参与动作的新鲜度校验；单日期控件保留日期原文，标准日期时间控件在用户只给出日期时按该日 00:00:00 填入并核对读回。自定义显示格式、范围或无法确认的控件不据占位文字推断精度。

表单预填只修改经应用审核的暂存字段，交接前核对同一表单和实时字段值。芋道批量填写单次最多20个字段，超出时整批拒绝，不截断执行；更长表单需分批，最后再交接。长表单可滚动到提交区域；无法核验时不报告完成。交接会提示用户核对并手动提交，助手不会点击提交按钮。

关闭业务写入的部署不判断保存意图（“审核”“改成”等词在这里只描述数据），也不做下述复核；部署未开放的填写、点击等页面步骤由服务端在答复后列为未执行。启用业务写入、但本轮未提供持久写入工具时，芋道对预填和办理类请求的完成声明复用现有完整请求复核，包括页面动作携带的直接结束答复及显式`finish(done)`。复核比较完整用户原话、程序记录的填写/高亮、真实表单和查询状态；仅打开列表或漏填字段不能当作整体完成。只读部署可把办理请求降级为标出确切目标业务按钮的交接，但答复必须明确尚未实际办理。存在疑点时最多交回一次纠正，复核不可用或纠正后仍不一致则不报告完成；纯查询和普通页面导航不因此增加复核。复核会增加模型调用，仍可能误判自然语言，不是任意请求完整性的确定性保证。

芋道 slim 在本轮没有对应的已安装写入操作时，会尝试先把目标记录筛选成唯一一条，再用 `highlight` 标出页面上的删除、审核、确认或启停按钮，交给用户自行操作。列表业务按钮的高亮准入要求当前应用列表 GET 只返回一条、同名按钮唯一，而且页面上可见的名称或单号（原生字段`name`或`no`）筛选值出自用户原话并与该 GET 的同一字段摘要一致。销售订单的这项单号投影只接受1–64位字母、数字、连字符或下划线。其它查询字段、未生效条件、多行结果或不匹配摘要不能作为这项交接证明。详情页还要求应用确认记录路由，并由当前账号的详情接口核对记录 ID；用户须明确给出该 ID，或给出经当前账号名称检索证实唯一的记录名。无法读出详情、名称重名且用户未给 ID 时不标出。标出控件只证明页面交接，不能算作业务动作已完成；目标或按钮无法确认时说明无法安全交接。危险业务按钮仍不允许通过页面点击执行。 系统用户页的状态开关也可交接：先把列表筛到唯一一行，核对原生表格与开关绑定，再用同账号重放当前实际生效的筛选，确认唯一返回同一编号，并与详情读取核对账号、昵称和当前状态；昵称须能唯一定位，或用户明确给出编号/账号。高亮只指向实际状态开关，不会点开关或报告已启停。

提交指示绑定本轮答复和确切控件。控件不可见或不可用时显示提示，目标失效、页面切换或用户开始新请求时清除。指示不授予写权限，状态只保存在当前浏览器。跨 iframe 沿用原高亮；遮挡判断采用浏览器命中采样，不保证识别不接收点击的覆盖层。

芋道客户详情返回的编辑资格仅针对客户记录本身。当前请求要修改关联联系人时，不查询或回传客户记录的编辑资格；在联系人详情发起修改时，按该联系人的权限行核对资格。修改所需的信息不完整时先询问，不代填猜测值。

跨轮追问可用上一轮答复中的单号等唯一标识定位，但必须重新读取当前记录；金额仍按同一记录的页面显示核对，不能只复述历史值。页面数值只作为当前可见记录的证据，对话框打开时不读取底层列表，不补入观察中未出现的值。

芋道 slim 收到明确“先填”“只填”“预填”“不提交”，或明确要求在编辑表单内改值且未要求保存的当前请求时，在调用 Skill 持久写入提案前由服务端拒绝提案，保持表单草稿交接路径；“不要直接提交”“别立即保存”等否定说法中的写入词不视为肯定指令，明确要求改完保存则不触发这一门禁；查找已有同名记录未命中时，会提醒同一 Agent 新建草稿仍可从新增表单完成。草稿表单的批量或单项填写在操作前按用户本轮点名的字段检查内容；批量调用整批核对，并与单字段输入一样参照当前表单的其它字段标签：未点名字段须有本轮用户给出的字面值；本轮未点名任何字段的指代请求可沿用此前用户点名的字段，不能从助手上一轮答复扩充字段。检查失败时整批不填，并要求缩小字段或向用户澄清。后续新请求若明确要求改值或提交，已安装 Skill 的持久写入仍须另行按新批准流程办理；上一轮已打开编辑表单不代表本轮只需预填。固定 v2026.09 的页面处理器审核范围现包含 ERP 供应商、仓库、产品的查询/分页/暂存表单，以及销售和采购订单的查询/分页与只读详情弹窗。明细加行按钮可按受限结构识别，也可由应用审核清单中的确切名称放行；两条路径都须通过危险按钮检查，并在操作后核对同一暂存表单仅新增一行。提交、状态变更和删除不在其中。

芋道开启原生写入时，只有当前处于已审核的 CRM 联系人列表、提案恰为新建联系人且仅含姓名、手机、职位、当前账号负责人及唯一可见 CRM 客户时，写入批准卡额外提供“只填到表单，我自己提交”。服务端把客户名称重新核对到提案中的客户 ID，再通过现有页面动作打开新增表单、选择客户、填写字段并核对实时表单；选择该项不派发业务写入。其他芋道写操作尚未声明提案转表单能力，不展示这个选项。页面返回 `stale_observation` 时表示该命令在派发前被拒，可重新观察后再尝试一次；已执行但核验不明的页面动作不自动重试。

在瘦回合内，模型决策调用和实际工具执行分别设上限：即使一次模型回复带多个工具调用，实际执行数也不超过配置的 `model_steps`（芋道当前为 24）；达到上限后只允许汇总已核实事实并结束。如果同一次点击、输入、选择、滚动或字段填写已经从相同页面状态执行过，再以相同参数重复会被拒绝；第四次重复会以未完成结束回合。观察轮次和新出现控件的临时标记不算进展。列表成功重新读取仍算状态变化，因此重复搜索可以执行。同一数据来源读回的行数由适配器作为结构化结果交给公共循环；在该来源没有非空结果的期间，两次空读会提示检查筛选，四次空读后只允许模型汇总已核实事实并结束，不再执行读取，未核实的部分必须说明。非空读取会清除该来源的空读计数。同一可唯一辨认的控件三次被以未审核为由拒绝时结束回合，无关搜索不会重置计数；每次仍重新审核，不合并有歧义的控件。滚动后页面观察没有变化时，会明确告诉模型屏幕内容没有变化。

实验性 Skill 运行时将任务知识加入既有查询/页面解析。应用安装 `ToolDefinition.effect_contract` 后，默认 `complete_request_check="single"` 从完整请求直接提出已安装操作，锁定应用投影出的效果。scope 选择知识和工具，其推测的类别不要求提案增加额外步骤。同一 Agent 可调用已注册且当前 actor 获准的只读工具及已加载知识附件，并在下次决策前收到结果。回复同时包含提案或结束时，只执行读取，要求模型观察结果后重新提案；此前已接受步骤及读取/纠正上限保持不变。提案要求工具响应和显式结束。首个写审批前，服务端检查 schema、原文来源、依赖、已声明查询/页面能力及可独立准备的效果。schema、来源和只读准备错误共用一次纠正预算，保留已接受步骤；准备纠正可先补查事实，再替换失败操作。空结束声明无效；纠正预算耗尽的校验错误保留失败状态，不隐式让渡到普通路径。显式保留约束只使用应用注册的字段身份，普通 patch 保留由应用负责。这些检查不独立识别字段交换，或提案遗漏的要求。

启用业务写入且安装效果合同 Skill 时，既有范围调用同时提供 select_skills。执行请求按描述选择一至四个已安装身份，不声明业务值或步骤。一次选择与一次范围声明可以同时返回，两者都须校验；范围提供定位提示，不增加另一份计划。普通查询、页面、准备与源码问题保留 declare_scope 及原解析器；完整原请求交给原生提案 Agent，选择不证明完整理解，也不声明写入意图。路由结构错误在准备前只纠正一次。写入关闭的集成保留原消息、schema 和恢复路径；没有效果合同的旧操作保留原准入。

可选的 `complete_request_check="anchored"` 在同一服务端 Agent 和预算内并行独立解读请求，声明动作、目标和用户提供的事实，不声明字段名；服务端将其与应用投影的草案及独立查询/页面义务比较。分歧允许准备前的一次整任务重声明。两份解读共享已加载的 Skill 业务知识，意图解读不读取工具 schema 或草案。值一致不能证明字段身份一致或一般可靠性。

Skill 规划读取按其发布的 JSON Schema 检查结构，包括不透明 ID 格式与动态过滤值。schema 引用只在本地解析；当前身份、字段语义与权限仍由应用检查。

共享实体读取先提供按描述定位，再将实体与字段参数约束为已经返回给同一 Agent 的 ID。字段查询需要已描述的实体，并只能使用该实体已返回的字段 ID。这只收窄 Skill 规划，普通读取与应用授权保留原合同。

原生提案保留仅用于规划的封装 `{"request_intent": "execute", "inputs": {...}}`，登记的原样输入继续绑定完整用户原文；显式保留约束放在封装顶层。单提案路径的 declare_goal 只声明读取、页面和预填，write_intent 为 false；执行声明进入既有的一次纠正，保留此前接受的操作。应用准备阶段投影实际业务效果、已定位身份、保留输入、默认值和复合效果；投影绑定进审批摘要，并在审批前与锁定请求核对。应用回执必须覆盖全部必需效果，mutation journal 才记录完成；已确认但核验不完整的效果保持不确定，绝不重试。普通非 Skill 查询/页面/源码回答保持既有解析器，没有效果合同的集成保留其原声明路径。

芋道三十项原生写操作按独立业务目标组织为二十四个 Skill 包：创建客户、在既有客户下新增联系人、修改客户资料、修改联系人资料、公海释放、领取、锁定、成交状态，线索维护、复合跟进、回款计划，ERP 供应商/仓库/客户/产品资料，系统部门/岗位/通知，商城品牌/分类，会员标签/分组及流程分类。跨包复用的消歧原则、层级与单位约定及实体区分资料集中维护在应用资产中，由应用装配为各包受控 references，单一来源、渐进加载；完成条件保留在正文内。关系名称及层级路径从当前账号读取后绑定外键；ERP 价格保持元、重量保持 kg。系统通知仅创建记录，不推送消息。客户公海/状态、回款计划及 OA 发布使用专用合同，展示和核验连带效果；OA 发布使用应用的动态下属规则，不支持固定接收名单。原生接口未暴露的负责人时间/历史元数据不声明为独立核验完成。芋道和合成 Contacts REST 集成实现了效果合同。新建定义记录不分配用户、会员或权限，不部署或发起流程。芋道需显式设置 `native_writes=True` 或 `--native-writes`，通过原生宿主唯一的模型循环执行；支持该操作的 Skill、完整可见审批和同 actor 回读仍为必要条件，浏览器提交仍关闭。当前字典选项约束提案，准备和派发时再次核对。静态解释引用已加载知识的确切段落。合同检查验证上述行为，不代表模型准确率或速度。

芋道跟进副效取决于主对象：客户/线索更新最近时间、下次时间、最近正文和已跟进标志；联系人不更新标志，商机不更新最近正文，合同只更新最近时间。同一份应用定义提供审批说明、效果投影和回读要求。必需字段在审批与派发前都须可读；已确认但副效不完整仍返回不确定。

范围检索先使用当前 actor 可见的实体名称，避免直接把英文名称片段逐项到全应用查找。请求已提到实体且没有单据编号时，名称在范围声明后仅于声明实体及关联实体定位；单据编号和没有实体名称的请求仍保留全局引用定位。延后查找不证明记录不存在，也不授予权限；普通查询保留独立解读和修复。

询问页面定义的源码问题仍是知识请求。启用源码的执行请求可在同一次路由调用中选择 Skill 并声明源码问题，现有源码范围保留当前比较所需的实时读取依赖。普通执行请求不需要源码槽；用户要求的查询、页面与源码交付仍保留在完整原文中。选择 Skill 不授予页面、数据或写入权限。

Skill 写入规划也会通过候选接口读取尚未唯一定位的范围名称，保留完整显示名。复合操作的读取范围包含当前账号实际可用工具声明的已审核实体，因此初步范围只命中操作主实体时，也能定位关联记录。初始候选不代表完整查询。single 路径的类型化目标引用准备错误可使用共享纠正预算和注册读取；仍无法消歧时，在任何写入前通过现有澄清界面提供当前候选。用户回复后重新声明并取得新的审批；已经派发或结果不确定的写入绝不重试。权限失败不进入模型纠正，没有澄清候选的缺失记录保留拒绝状态。
