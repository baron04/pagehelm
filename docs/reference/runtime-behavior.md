# 运行时行为详情

README 只保留稳定概览。本页记录影响接入、使用和运维的运行时行为与限制。设计取舍见[系统设计](../concepts/overview.md)；接入合同见[应用 Adapter 合同](../guides/integrate-an-application.md)、[Skill 与类型化操作](../concepts/skills-and-tools.md)与[持久运维](../guides/operate-durably.md)。

以上说的是已实现的路径，不是总体成功率。仓库没有规模足够的公开基准来证明它优于其它浏览器 Agent。

## 已实现能力

- 目标式回合让模型对照应用索引声明请求。索引由 Adapter 以当前用户身份编译，包含实体、字段、页面、视图、筛选、分组、页签和控件。服务端随后确定性地解析每一项声明：记录用应用自己的名称搜索，字段值用类型化读取，计数、求和与数值极值用限定范围的查询，页面用已审核路由，页签按可见名称，筛选和分组按页面自身状态，要做的修改则把对应控件高亮出来交给用户。答复由解析出的值生成，不采用模型的文字，所以回合报告的事实都是它读到的。做不到的部分如实说明；所有声明项都落实后，回合才算完成。多条记录都符合又无法区分时，回合会追问是哪一条。指名的记录不存在时，不会改成新建。条件支持数字、日期和文本上的比较；日期可以是某天、某月、某年、区间或命名时段，按用户时区计算。声明是模型输出，可能选错实体、字段或范围；这条路径会增加模型调用和耗时，不是一次调用完成的回合。
- 目标式回合可以预填表单并交接：填入用户给的值，核对各字段随后显示的内容，高亮提交按钮，但从不提交；无法确定填对的值留给用户并说明。表单预填默认关闭，需要应用安装已审核的表单端口并设置 `allow_form_prefill=True`。通过页面自身查询控件做筛选同样由应用显式开启，并且要等应用报告查询已生效才算完成。
- 挂接编译后的源码图谱时，索引可以带上部署源码里的规则（控件何时显示或禁用、字段何时必填或只读、方法在什么条件下拒绝），答复会引用准确的源码行。Adapter 还可以带上本组织经过审核的用语约定，说明某些词在这里指什么。
- 服务端 ReAct 循环在每次决策前接收工具结果与新的页面观察，并受步骤、时间、token 和模型花费上限约束。集成方可以显式开启：绑定当前 actor 的数据读取（`AgentTurnConfig.data_reads`）、由应用签发的动作效果（`action_policy`）、导航的渲染路由证明（`require_page_route`）、事先的任务声明（`require_task_contract`）。它们默认都关闭，都不授予写权限。
- 应用拥有的 Skill 使用 `SKILL.md`（YAML 元数据和 Markdown 正文），附带有界、按需加载的参考资料。目标式规划器只为已加载包的可读文本附件提供资源读取工具；正文已经加载。Skill 描述业务知识、查询、页面或写入流程；独立注册的类型化工具定义真实能力、actor scope 和效果。当前事实来自应用读取。显式启用后，可按需检索绑定部署的源码，出处留在服务端；源码检索可选且不授予权限。
- 逐步 Agent 可以在当前页面观察的有界、已脱敏证据中搜索或翻页。这不会搜索应用数据，也不能证明某项内容不存在。
- 应用无关的实体读取合同可以发现当前 actor 可读的业务实体并做有界读取，不必为每个实体写一份 Skill。另有记录引用读取，按名称或编号找候选；有歧义时返回全部候选，不替用户选。Odoo 与结构不同的合成 Contacts REST Adapter 运行同一套合同测试。
- 另有只读的 `find_page_entries`，按当前 actor 的页面和动作元数据给候选排序，只为 Adapter 审核过的独立目的地返回路由。这不代表应用的每个页面都可操作。
- 只读的 `resolve_goal_candidates` 可在一次调用中组合最多三个问答、页面或交接目标的候选检索。它不替用户选候选，也不代表目标已完成。
- 可选的应用无关当前表单合同为无 Skill 场景提供安全的标量字段预填兜底（`describe_form`、`prepare_form`、`prefill_form`）。它输入草稿、核对字段的实时值，从不点击提交控件。Odoo 的标准新建表单在离开时会自动保存，所以通用的手动提交预填在那里会被拒绝；它的类型化客户新建和编辑交接需要开启写入确认通道并取得新的审批。
- Turn 按来源职责组装上下文：当前页面是实时基线；后续追问会带上有界的对话历史；Skill 按当前任务选取；部署源码按需检索并引用，不整体注入。
- 浏览器动作会按当前观察和应用路由策略校验。页面观察只覆盖当前视口，最多暴露 200 个可操作控件。操作页面需要用户同意：每次提问中的首次页面操作（打开页面、点击、填写、选择、提交、返回、应用筛选）用一张可见卡片征得同意，同一轮后续页面操作沿用这次同意；下一次提问重新征求。工具循环式回合修订了对任务的理解后也会重新征求。读取、滚动、等待和高亮不需要征求。这份同意不是写入审批：每次业务修改仍在各自的卡片上单独确认。
- `goto` 的地址已经是当前地址时，Runtime 保留当前文档并回报已在页面；目标是否已正确渲染仍由服务端的页面状态核验。跨页面跳转优先交给应用提供的 `openPage`，只有应用无法接管时才加载文档。
- 助手无法代做的页面操作，可以用 `highlight` 标出一个当前可见、具名的控件，并在不点击、不提交的情况下结束回合。这是引导式交接，不代表业务修改已经发生。
- 收在折叠菜单里的控件（比如记录“操作”菜单里的“删除”）在任何应用里用同一个办法找到：目标式回合最多展开三个页面自己声明为折叠的菜单，标出控件，并在答复里说明它在哪个菜单里。不会选中菜单里的任何一项。
- 当请求指向一个页面状态（打开某个界面、切换页签、应用筛选或分组、到达某条记录）时，Agent 先用 `set_target` 声明这个状态，服务端把每次新的观察与声明比对后才报告到达。声明目标不授予任何权限。用户读到的那句话由观察到的页面生成，不采用模型的文字。
- 通用点击作为动作可以保持禁用，同时由应用通过可选的点击策略放开其中一部分。Odoo 参考集成放开页签、主页按钮、指向已审核页面和记录的链接，以及这些页面上具名的视图切换、翻页、搜索和菜单控件。工作流按钮、新建、操作、行选择、行内编辑和未审核页面仍被拒绝。
- 声明了页面只读守卫的集成，可以在当前观察中提供最多 32 个由应用列出的筛选与分组选项；可选的 `apply_facet` 工具应用其中一个，并以新观察到的生效状态为准。
- 应用可以声明 `page_write_guard` 路径，在 Agent 操作页面期间把已登录会话变成只读。Odoo 的 `woa_runtime` 1.5 实现了它：窗口开启期间，该会话的每个请求都在只读事务中执行。请先部署 1.5 版 addon，再部署这个 Adapter。
- 已注册的类型化读取不要求匹配 Skill。包可以在 `agents/woa.toml` 中声明经过审核的实体和页面身份，用于选择知识，不依赖写工具安装。集成可要求写入绑定显式加载的 Skill 及其操作清单。清单只限制提案，不安装工具或授予权限。工具 schema 按部署的写入开关和当前 actor 的权限范围过滤，派发时再次校验。
- 开启业务写入并安装带效果合同的 Skill 后，普通目标可在变更、拒绝或仅源码出口前征询执行一次。未要求执行或没有匹配操作时，提案可在批准前让渡回普通路径。范围声明无效后，让渡在未启用源码时继续原有完整索引恢复；启用源码的部署保留范围依赖拒绝。普通查询/页面保持原流程；仅源码请求可能多一次选择调用。写关闭时使用普通解释器，并可加载 Skill 知识。该准入机制已有合成合同检查，不能据此认定真实模型成功率。已实测的 Token Plan DeepSeek 端点使用供应商 `auto` 编码要求工具声明，客户端仍拒绝没有工具调用的响应。
- 只有用户的请求本身能要求写入。Skill 任务声明从完整请求解释执行意图，范围提示或工具可用性不能证明该意图。解释仍可能出错，包括否定请求。记录和页面文字不授予权限，每项写入仍需完整可见审批卡片。
- 写入默认关闭。核心 turn 配置默认关闭所有可能触发应用写入的浏览器动作（包括导航），Adapter 必须显式开启自己审核过的子集。开启的写入把准确的效果和对象绑定到一次性的新审批上，最多派发一次，并通过应用核验结果。超时或结果不确定的写入记为 `indeterminate`，不会自动重试。
- 芋道模型回合的页面策略从部署版本的菜单与已知记录路由生成清单，仍由服务端的动作准入、应用只读窗口与方法围栏逐次判断。查询行的下载、导入、删除及提交类控件被拒；暂存表单只允许预填和交接。查询重置须有新一版应用列表读取，且可见查询控件的值与这次读取的参数摘要一致；浏览器对空文本框省略 `value` 属性时按空值核对，未显示字段若变化则不确认。页面观察为每个可见表格行提供有界的“列名=值”；对应列表接口与当前页面的读取路径一致时，`call_api` 给字段附上从部署前端源码编译的页面列名。负责范围列表中的空结果不证明详情无权限；查找会继续读其它实体，确切详情权限以同 actor 的详情 GET 为准。
- 芋道客户列表的原生页签有单独的处理器审核。当前账号的菜单页、已渲染列表和成功应用的列表读取都成立时，才能点击页签；核验要求同一页签实际选中，且同一列表接口以不同查询参数成功重新读取。其他列表页签仍须逐页审核。记录详情页的页签仍核对当前记录和实际选中状态。
- 芋道原生写入把应用返回的错误类别和代码脱敏记录为对账证据。已有确切目标 ID 的更新或状态变更，错误响应后可以用同 actor 回读证明完整效果；没有完整证明时仍为 `indeterminate`，不会据一次未查到效果的读取改判失败。复合跟进可能在应用报错前已经插入记录，故没有可归属的确认 ID 时保持不确定。
- 短期 actor/tenant/workspace 主体可绑定浏览器 capability、工具 scope、审批、mutation、审计记录和撤销状态。
- React 助手面板只是服务端状态的视图。启动按钮从脚本运行起就在页面上。用户发送消息或重新打开对话时建立会话，空闲五分钟后释放；失效的会话在下一条消息时恢复，启动失败会在面板里说明并提供重试。打开面板时会恢复当前用户在服务端的历史。
- 模型回合的只读工具可附带应用签发的页面或记录目标。服务端只把已完成读取中、名称出现在最终答复里的唯一目标作为独立链接数据投影到结果下方；同名的多个记录、跨域地址、带查询参数或片段的地址、未完成或写入回合都不附链接。芋道用当前账号的菜单读取签发唯一页面目标，用同账号详情读回签发唯一记录目标；Contacts 测试应用用当前账号的页面目录及二次联系人读取签发列表页和记录目标。链接由用户点击，浏览器只在本地检查可见表单、对话框和未保存输入：确认无草稿且应用提供 `openPage` 时走应用路由；否则在新标签页打开。应用路由拒绝时，已预留的新标签页承接目标地址。浏览器不把草稿状态送往服务端。
- 新对话的示例由应用提供，点击只填入草稿。翻阅或加载较早的对话记录时，面板保持当前阅读位置，并支持返回最新消息。
- 一个会话可以同时在多个页面上打开。所有页面看到同一段对话；回合在发起它的页面上运行，只有那个页面会收到页面指令。
- 面板支持浮层和抽屉，所选形态与窗口位置保存在当前浏览器。抽屉可能收窄宿主页面；应用按视口定位的弹窗可能被助手遮挡，接入时需要验证。
- 可选 SQLite 存储提供 session 所有权、进度 outbox、有界会话上下文、mutation journal、备份和明确的人工结算。

## 执行器与集成细节

模型驱动循环中，即使点击页签的初始回执仍在加载，也可根据应用核验通过后的稳定观察结束。表单交接核验通过且仍对应当前页面时，服务端明确提醒用户核对后手动提交；交接失败或仍需补充信息时不报告交接完成。源码工具用于用户明确提出的实现问题；当前业务值和配置需要从应用读取，不能以源码默认值代替。工具选择仍取决于模型。

芋道原生宿主只使用 `slim`，由应用无关的 `ModelDrivenTurnExecutor` 驱动。启动必须提供版本匹配的 v2 方法围栏、带审核路由和处理器的 `--native-page-policy`；live forms 和应用自己的只读窗口始终启用。缺少或不兼容的配置在模型和网络启动前拒绝，不自动回退。旧 `goal`、`page-agent` 的宿主选项已删除，传入会由参数解析拒绝。写入仍默认关闭，浏览器提交始终关闭。助手打开页面时，由应用自己的 Vue Router 在用户所在的文档里打开，页面重新构建、路由历史保持完整，所以助手窗口不会收起，应用也不用重新启动；应用无法接管的地址才按整页加载；地址与当前相同时保留文档。slim 回合保留目标式回合的协议（身份、本轮页面操作同意、写入观察、回执和预算），由模型从一小组固定工具里逐步选择下一步——当前账号自己的菜单、以当前账号身份调用的应用只读接口，以及 Runtime 的点击、填写、选择、滚动、跳转和高亮。它只在方法围栏加应用自己的只读窗口下启动，从不按提交控件；方法围栏会拒绝的 GET，它的接口工具也不会调用。不带 `--native-writes` 时它不做任何写入。带上之后，同一段对话可以加载已安装的 Skill（`load_skill`）并提出该 Skill 的类型化操作，操作在加载后成为带已安装输入 schema 的工具。每个提案都走共享的写服务：以当前账号做只读准备，已登记的字面输入与用户本人的话逐字比对，应用对所准备效果的投影与提案输入比对，一次完整可见的批准，一次派发，同账号回读。在征求用户批准之前被拒绝的提案回到同一段对话，可在有限次数内修正；被拒绝批准、被应用拒绝或结果不确定的写入结束本回合，不再重发。目标式执行器的 Skill 选择、单提案和让渡步骤不在这个回合里使用。跨回合它只保留宿主的有界会话状态：用户的原话、每回合的答复和该回合已核对的写入，默认最近四回合、32 KiB，按会话标识持久化；所以宿主重启之后对话可以接着进行，此前回合读到的数据和看到的页面要重新读取。接口读取和按名称找记录的结果在告诉模型之前先隐去凭据：本适配器从不读取的字段（密码、密钥、令牌、渠道配置）、名称表明是凭据的配置项的值，以及任何字符串里的凭据或会话参数赋值；其中的行、值和名称作为应用数据围起来，模型被告知只把它们当事实读、不当指令执行。当前登录用户在应用里本来就能读到的业务字段不做遮蔽。回合进行中，面板时间线在页面动作之间说明它在做什么：在查找哪个页面、数据来源或记录，正在读取业务数据以及读回了哪个列表的多少条，正在准备一次更改，正在核对结果；这些句子由服务端给出。宿主在用户的会话建立时默认于后台读好该用户的菜单、建好该用户的应用索引，让这些读取与回合开始前的等待重叠。它只预热菜单/API 说明和 outline，不预读明细表详情。读取量取决于安装的模块。冷启动测量由测试配置关闭预热，生产 CLI 不提供预热开关；预热结果不能代表冷启动性能。目前只在小规模合成评测集上运行过。

芋道宿主建立或续期会话时，会先用页面提交的访问令牌向应用核实身份，再读取组装可选写入工具所需的字典。身份读取或随后的字典读取返回 401 时，bootstrap 保留 401，页面 loader 用应用的刷新令牌续期并重试一次；应用返回 403 时保留权限拒绝。上游读取故障仍是 503，不会触发令牌刷新。身份未核实前不建立新会话，也不派发业务操作。
芋道原生 API 经过页面代理时，身份失效的请求在代理处拒绝且不派发，响应采用应用自己的 HTTP 200、`code=401` 格式，让现有前端续期访问令牌；页面批准接口仍用 HTTP 401 拒绝无效身份。续期是否成功由应用的刷新令牌决定。

当前页曾有失败读取而处于 `blocked` 时，模型仍可请求离开该页：只有同源、当前账号菜单可见且经部署审核的确切目标路由可进入跳转准入；`pending` 状态、当前页控件操作和未审核目标仍被拒绝。跳转成功仍须由目标页的就绪状态与应用渲染路由证明核验，地址变化本身不算完成。`invalid_target` 只说明当前页状态或目标地址未通过校验，不能据此断定菜单未审核或账号无权限。

芋道的 `call_api` 以当前账号身份调用只读接口；带 `fields` 时从所请求页起最多跟读 5,000 行。只有从第一页开始、分页总数有效且稳定、跨页记录 ID 不重复、实际读到总数时，才计算全量数值合计与极值、日期列的每月行数，以及类型和状态列的分组与合计。其它情况明确报告未读完，不提供这些全量统计；单页接口返回的 `total` 与本次行数分别说明。按“我负责的、我参与的、下属负责的”合并账号可见记录时，普通逐页读取未完成且未要求 `fields`，适配器可再按记录编号逐页计数，最多读取 20,000 行，跨范围去重后只返回总数，不把这些业务行送入模型。超过上限、总数变化、页间重复或读取失败时，不给模型部分去重数或部分记录，明确报告无法得出可见总数、全量名单或不存在结论；审计仍保留实际读取行数与完整性标记。没有事务快照时，分页核对不能证明并发变化期间的完整性。工具与阶段合并参数见[执行器](../concepts/executors.md)，部署参数见[芋道部署说明](../../examples/yudao/deploy/README.md)。

芋道 `call_api` 成功读取后，服务端审计记录已安装接口路径、查询参数名、页码和页大小、已发布的选取字段名、实际读取行数、声明总数与是否读全；筛选值和记录内容不写入审计。审计能复核调用路线及读取范围，不能单独证明模型选择的筛选条件符合用户意图。

公共模型循环校验闭合的工具 schema，把类型化结果和新鲜页面观察交给同一个 Agent，并使用应用签发、一次消费的动作或暂存步骤授权。芋道负责菜单/API 知识及日期、分页、明细过程；结构不同的合成 Contacts REST/HTML 应用验证同一核心。最后一次页签点击可以附带答复，只在确切动作经过保护与应用核验、同一标识的页签实际选中后结束。芋道也可在一批分页要求的页码、每页条数全部符合应用当前列表回读，并绑定本次确切核验命令后直接结束。名称查找给出唯一命中已读到的编号；全局未命中明确索引的覆盖边界并附相关已发布接口元数据，元数据不证明记录存在或不存在。普通模型结束标为 `not_claimed`：局部动作回读不独立证明整个请求或模型答案正确。配置部署源码时，同一循环提供 allowlist 源码检索、有界行读取和可选 Git 历史。源码结论必须引用本轮证据和原文支持，答复由服务端标明绑定的源码版本；纯源码回合检索后仍找不到直接依据并选择拒答时，服务端固定说明已查的来源和结论边界，不采用模型自写的拒答内容。这些检查证明引用归属，不证明语义正确。纯源码回合无需浏览器观察或业务元数据；调用应用工具前必须绑定请求页的真实观察。普通操作不要求源码仓库。

芋道查询下拉绑定当前页面的选项标签和原生标量值，再核验成功生效的查询。原生日期范围选择只在输入框所拥有的弹窗内定位确切日期；目标月份不在当前两个月面板时，通过该弹窗的上个月或下个月按钮有界移动，再核对目标日期，无法核对时拒绝该页面动作。只有明确审核过的查询表单展开按钮可显示更多字段。类型化数据权限拒绝会结束回合；接口结构纠正只报已安装字段，不回显被拒绝的输入。

芋道 slim 对明确只问业务状态、且没有页面操作、金额核对或修改要求的提问，只提供当前账号的只读查找与接口工具；模型即使提出页面动作也会被拒绝。带有页面或金额要求的混合请求仍使用原有工具与核验。

slim 的记录导航使用当前账号的实体/页面 outline，在动作前后精确读取目标详情，不编译无关的内嵌明细元数据。暂存表单选择时，slim 直接调用 Runtime 在同一归属列表内的有界选择：由它展开列表、精确查找标签，拒绝有歧义或禁用的选项。标签不存在时，交回该列表有界、脱敏的标签，不自动替换名称。新增草稿中类型已明确的关联字段，提示模型先尝试用户给的名称，再依据本字段选项纠正；本地选项不足时才补充范围明确的读取。筛选字段须先出现在当前观察中，折叠字段先展开再填写。下拉展开后输入框没有唯一的当前控制器序号时跳过收起，仍须核验草稿未变及表单身份。只有 Runtime 证明未选中选项且本地草稿未变，再由应用的可选证明确认同一表单和账号时，才允许纠正；其它已发出但核验失败的草稿动作结束回合。审核过的表单入口可以与导航合并（`goto(open=...)`）。按字段名填写可带 `then_highlight` 和 `answer`：每次输入仍逐个准入、核验，之后服务端回读用户给出的字段及此前观察到的未填写字段，再由既有 Runtime 表单交接核验所填字段的实时值并标出提交按钮。同一批填写可以先通过精确命名的已审核按钮新增 1–4 行（`add_lines`）；每次建行必须保留同一表单及此前字段值。无标签的明细控件按当前精确 ref 和实时表单实例核验。已审核的 ERP 销售订单和其它入库表单，产品自动带出的单价由同一账号精确读取产品后核对；其它未填写值仍须保持原样。完整的筛选批次可带 `then_click` 和 `answer`，仅凭本工具真实且经应用核验的生效查询回执结束。字段缺失或填写失败时不会点击搜索。不完整、被替换或屏幕外的字段需要继续观察。浏览器提交和写入审批规则不变。客户详情导航从当前账号的实时应用权限行反馈编辑资格，不由编辑控件是否可见推断。CRM 客户名称在当前账号各业务范围未命中时，用应用普通名称列表判断是否为范围外记录；仅客户的这项已审核范围语义允许返回类型化权限拒绝。CRM 联系人的范围查询会与同账号普通联系人列表的同名候选合并去重，避免范围内外同名时误判为唯一；普通列表新增的候选还须经精确详情 GET 验证身份与访问权，失败时保留应用返回的拒绝，不据列表可见性推断无权打开。名称查找的可选列表预览只传入接口声明的参数，需要额外输入的接口跳过预览。按列投影的 API 结果会列出已返回、有文档但未展示的列，供模型补读。动作拒绝和回执保留明确错误码与派发状态，审计记录脱敏；后续等待不覆盖已确定的动作结果。每次读取仍由应用认证和授权；凭据失效或变化时拒绝继续执行。表单和写入准入仍须核对当前权限。

表单预填只修改经应用审核的暂存字段，交接前核对同一表单和实时字段值。长表单可滚动到提交区域；无法核验时不报告完成。交接会提示用户核对并手动提交，助手不会点击提交按钮。

芋道 slim 在本轮没有对应的已安装写入操作时，会尝试先把目标记录筛选成唯一一条，再用 `highlight` 标出页面上的删除、审核、确认或启停按钮，交给用户自行操作。列表业务按钮的高亮准入要求当前应用列表 GET 只返回一条、同名按钮唯一，而且页面上可见的名称筛选值出自用户原话并与该 GET 的字段摘要一致；详情页则要求应用确认记录路由。标出控件只证明页面交接，不能算作业务动作已完成；目标或按钮无法确认时说明无法安全交接。危险业务按钮仍不允许通过页面点击执行。

提交指示绑定本轮答复和确切控件。控件不可见或不可用时显示提示，目标失效、页面切换或用户开始新请求时清除。指示不授予写权限，状态只保存在当前浏览器。跨 iframe 沿用原高亮；遮挡判断采用浏览器命中采样，不保证识别不接收点击的覆盖层。

芋道客户详情返回的编辑资格仅针对客户记录本身。当前请求要修改关联联系人时，不查询或回传客户记录的编辑资格；在联系人详情发起修改时，按该联系人的权限行核对资格。修改所需的信息不完整时先询问，不代填猜测值。

跨轮追问可用上一轮答复中的单号等唯一标识定位，但必须重新读取当前记录；金额仍按同一记录的页面显示核对，不能只复述历史值。页面数值只作为当前可见记录的证据，对话框打开时不读取底层列表，不补入观察中未出现的值。

芋道 slim 收到明确“先填”“只填”“预填”或“不提交”的当前请求时，在调用 Skill 持久写入提案前由服务端拒绝提案，保持表单草稿交接路径；“不要直接提交”“别立即保存”等否定说法中的写入词不视为肯定指令；查找已有同名记录未命中时，会提醒同一 Agent 新建草稿仍可从新增表单完成。后续新请求若明确要求改值或提交，已安装 Skill 的持久写入仍须另行按新批准流程办理；上一轮已打开编辑表单不代表本轮只需预填。固定 v2026.09 的页面处理器审核范围现包含 ERP 供应商、仓库、产品的查询/分页/暂存表单，以及销售和采购订单的查询/分页与只读详情弹窗。明细加行按钮可按受限结构识别，也可由应用审核清单中的确切名称放行；两条路径都须通过危险按钮检查，并在操作后核对同一暂存表单仅新增一行。提交、状态变更和删除不在其中。

在瘦回合内，模型决策调用和实际工具执行分别设上限：即使一次模型回复带多个工具调用，实际执行数也不超过配置的 `model_steps`（芋道当前为 24）；达到上限后只允许汇总已核实事实并结束。如果同一次点击、输入、选择、滚动或字段填写已经从相同页面状态执行过，再以相同参数重复会被拒绝；第四次重复会以未完成结束回合。观察轮次和新出现控件的临时标记不算进展。列表成功重新读取仍算状态变化，因此重复搜索可以执行。同一数据来源读回的行数由适配器作为结构化结果交给公共循环；在该来源没有非空结果的期间，两次空读会提示检查筛选，四次空读后只允许模型汇总已核实事实并结束，不再执行读取，未核实的部分必须说明。非空读取会清除该来源的空读计数。同一可唯一辨认的控件三次被以未审核为由拒绝时结束回合，无关搜索不会重置计数；每次仍重新审核，不合并有歧义的控件。滚动后页面观察没有变化时，会明确告诉模型屏幕内容没有变化。

实验性 Skill 运行时将任务知识加入既有查询/页面解析。应用安装 `ToolDefinition.effect_contract` 后，默认 `complete_request_check="single"` 从完整请求直接提出已安装操作，锁定应用投影出的效果。scope 选择知识和工具，其推测的类别不要求提案增加额外步骤。同一 Agent 可调用已注册且当前 actor 获准的只读工具及已加载知识附件，并在下次决策前收到结果。回复同时包含提案或结束时，只执行读取，要求模型观察结果后重新提案；此前已接受步骤及读取/纠正上限保持不变。提案要求工具响应和显式结束。首个写审批前，服务端检查 schema、原文来源、依赖、已声明查询/页面能力及可独立准备的效果。schema、来源和只读准备错误共用一次纠正预算，保留已接受步骤；准备纠正可先补查事实，再替换失败操作。空结束声明无效；纠正预算耗尽的校验错误保留失败状态，不隐式让渡到普通路径。显式保留约束只使用应用注册的字段身份，普通 patch 保留由应用负责。这些检查不独立识别字段交换，或提案遗漏的要求。

启用业务写入且安装效果合同 Skill 时，既有范围调用同时提供 select_skills。执行请求按描述选择一至四个已安装身份，不声明业务值或步骤。一次选择与一次范围声明可以同时返回，两者都须校验；范围提供定位提示，不增加另一份计划。普通查询、页面、准备与源码问题保留 declare_scope 及原解析器；完整原请求交给原生提案 Agent，选择不证明完整理解，也不声明写入意图。路由结构错误在准备前只纠正一次。写入关闭的集成保留原消息、schema 和恢复路径；没有效果合同的旧操作保留原准入。

可选的 `complete_request_check="anchored"` 在同一服务端 Agent 和预算内并行独立解读请求，声明动作、目标和用户提供的事实，不声明字段名；服务端将其与应用投影的草案及独立查询/页面义务比较。分歧允许准备前的一次整任务重声明。两份解读共享已加载的 Skill 业务知识，意图解读不读取工具 schema 或草案。值一致不能证明字段身份一致或一般可靠性。

Skill 规划读取按其发布的 JSON Schema 检查结构，包括不透明 ID 格式与动态过滤值。schema 引用只在本地解析；当前身份、字段语义与权限仍由应用检查。

共享实体读取先提供按描述定位，再将实体与字段参数约束为已经返回给同一 Agent 的 ID。字段查询需要已描述的实体，并只能使用该实体已返回的字段 ID。这只收窄 Skill 规划，普通读取与应用授权保留原合同。

原生提案保留仅用于规划的封装 `{"request_intent": "execute", "inputs": {...}}`，登记的原样输入继续绑定完整用户原文；显式保留约束放在封装顶层。单提案路径的 declare_goal 只声明读取、页面和预填，write_intent 为 false；执行声明进入既有的一次纠正，保留此前接受的操作。应用准备阶段投影实际业务效果、已定位身份、保留输入、默认值和复合效果；投影绑定进审批摘要，并在审批前与锁定请求核对。应用回执必须覆盖全部必需效果，mutation journal 才记录完成；已确认但核验不完整的效果保持不确定，绝不重试。普通非 Skill 查询/页面/源码回答保持既有解析器，没有效果合同的集成保留其原声明路径。

芋道三十项原生写操作按独立业务目标组织为二十四个 Skill 包：创建客户、在既有客户下新增联系人、修改客户资料、修改联系人资料、公海释放、领取、锁定、成交状态，线索维护、复合跟进、回款计划，ERP 供应商/仓库/客户/产品资料，系统部门/岗位/通知，商城品牌/分类，会员标签/分组及流程分类。跨包复用的消歧原则、层级与单位约定及实体区分资料集中维护在应用资产中，由应用装配为各包受控 references，单一来源、渐进加载；完成条件保留在正文内。关系名称及层级路径从当前账号读取后绑定外键；ERP 价格保持元、重量保持 kg。系统通知仅创建记录，不推送消息。客户公海/状态、回款计划及 OA 发布使用专用合同，展示和核验连带效果；OA 发布使用应用的动态下属规则，不支持固定接收名单。原生接口未暴露的负责人时间/历史元数据不声明为独立核验完成。芋道和合成 Contacts REST 集成实现了效果合同。新建定义记录不分配用户、会员或权限，不部署或发起流程。芋道需显式设置 `native_writes=True` 或 `--native-writes`，通过原生宿主唯一的模型循环执行；支持该操作的 Skill、完整可见审批和同 actor 回读仍为必要条件，浏览器提交仍关闭。当前字典选项约束提案，准备和派发时再次核对。静态解释引用已加载知识的确切段落。合同检查验证上述行为，不代表模型准确率或速度。

芋道跟进副效取决于主对象：客户/线索更新最近时间、下次时间、最近正文和已跟进标志；联系人不更新标志，商机不更新最近正文，合同只更新最近时间。同一份应用定义提供审批说明、效果投影和回读要求。必需字段在审批与派发前都须可读；已确认但副效不完整仍返回不确定。

范围检索先使用当前 actor 可见的实体名称，避免直接把英文名称片段逐项到全应用查找。请求已提到实体且没有单据编号时，名称在范围声明后仅于声明实体及关联实体定位；单据编号和没有实体名称的请求仍保留全局引用定位。延后查找不证明记录不存在，也不授予权限；普通查询保留独立解读和修复。

询问页面定义的源码问题仍是知识请求。启用源码的执行请求可在同一次路由调用中选择 Skill 并声明源码问题，现有源码范围保留当前比较所需的实时读取依赖。普通执行请求不需要源码槽；用户要求的查询、页面与源码交付仍保留在完整原文中。选择 Skill 不授予页面、数据或写入权限。

Skill 写入规划也会通过候选接口读取尚未唯一定位的范围名称，保留完整显示名。复合操作的读取范围包含当前账号实际可用工具声明的已审核实体，因此初步范围只命中操作主实体时，也能定位关联记录。初始候选不代表完整查询。single 路径的类型化目标引用准备错误可使用共享纠正预算和注册读取；仍无法消歧时，在任何写入前通过现有澄清界面提供当前候选。用户回复后重新声明并取得新的审批；已经派发或结果不确定的写入绝不重试。权限失败不进入模型纠正，没有澄清候选的缺失记录保留拒绝状态。
