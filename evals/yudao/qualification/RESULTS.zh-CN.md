# v7 首测与三模型对照：2026-10-02

当前能力、准确率和冷请求速度仍未达到用户期待。独立编写的 v7 首测完整正确 **53/64（82.8%）**，8 题部分完成、3 题失败；当前 Qwen 配置服务端耗时中位 **16.97 秒**、P95 **41.81 秒**。同一困难子集的 DeepSeek Flash 明显更快，但三个候选配置都没有达到 90% 完整正确率，不能据此直接宣布线上达标。

## 冻结与方法

- 产品基线为 `420eed3a`；首测的产品与评测工具版本为 `60c3721c1baa108b910af90b482bb239040f2842`。运行前、后检查的 323 个产品文件 hash 全部一致。
- [v7](../v7/AUTHORSHIP.zh-CN.md)由独立子 agent 在运行前编写：64 题，58 题要求完整交付、2 题澄清、3 题能力限制、1 题权限受限下部分交付；11 题先验标为 stretch。覆盖 10 客户、30 合同、8 供应商、7 流程及合成部署源码。不是生产数据。
- 首次模型调用前冻结题目、数据、rubric 和 [30 题比较子集](../v7/comparison_ids.json)。时间固定为 `2026-09-30T12:00:00+08:00`，同时进入上下文和适配器。manifest SHA256 为 `00f8778f7683813cdac34130bfa8cc0a8762ec8368e4b5c7aaf9f5673df19583`，运行后全部文件 seal 一致。
- 作者没有查看旧题或轨迹；公开元数据提取意外带出一段测试代码，根 agent 做了预审并改正一道不自洽的歧义题。详见作者声明。因此是**首次运行前独立编题**，不是完全严格的外部盲测。首次结果没有用于改题、重跑挑最高分或调整产品。
- 调用真实模型和现有 `GoalTurnExecutor`/原生适配器，API 为有分页、scene、权限的合成 client，浏览器为 transport double。每题新 executor、冷声明缓存；供应商 prompt cache 没有强制清空。**时间是服务端回合时间，不是面板端到端时间；导航只能证明模拟收据到达，不能证明真实 DOM 渲染。**
- 同一 30 题、同一代码、工具、输入与 token 上限，三个候选均关闭推理；当前 Qwen 生产配置另保留首测中的相同 30 题作为参考。两条 lane、五题一个块轮换模型顺序。供应商负载/cache 未控制，每个配置每题只测一次；30 题不支持总体可靠率或统计显著性的结论。
- 第一层保留冻结正则、状态、引用字节、路由和禁止写入筛查。第二层由独立子 agent 按必要事实逐题匿名语义复核，不给模型名、自动分数或产品实现；partial 不计正确。根 agent 补充冻结数据中的 ID→名称映射，并核对计费、路由终态和范围。审核并非独立人工标注，仍可能有判断误差。
- 一般查询后的多余列表导航作为行为缺陷单列，冻结 rubric 没有一律禁止，不能事后增加规则改低分；显式禁止操作仍需遵守。审核输入曾误取初始 observation 为 final URL，已用 `goal_page_settled` 纠正并独立重审，没有更改模型输出、题目或冻结判分器。
- rubric 和 oracle 从未进入产品模型或检索索引。异常、拒绝、权限题保留在原分母；没有访问生产账户，没有业务写入。

## 速度瓶颈与下一步顺序

本次数据证明存在提速空间。Flash 非思考候选最值得进一步验证，但先修共同语义问题，再做新版本回归与真实 UI 验收；当前实验没有切换线上模型。

1. **先修确定性日期与范围错误。** `goal/resolve/scope.py::_date_condition` 对 `!=` 没有专门分支，落入等值日期范围，这是 14 的代码证据，不是纯模型推测。覆盖检查又可能把“不能算进来”的负例当成缺失正条件。41 则需区别“值非空”和“值大于零”，不能只检查合计数值。
2. **用已给条件完成消歧。** 17、19 在名字相似时卡住，缺少把日期、关系等约束一起作用于候选的能力。保持账号绑定、数据访问上限与真实歧义澄清，不能简单改成总选最短或第一个名称。
3. **保留混合目标并让规则与事实汇合。** 43 会在范围阶段丢工程职责；44 虽读取当前状态，却让源码回答与动态数据彼此隔离，未完成应用判断。应单独跟踪每个交付项的完成和依赖。检索索引没有某个名称，也不能当作实时记录不存在（21、45）。
4. **明确极值契约与可用字段。** 36 将最大值变众数/求和；缺失金额的完整求和保护是正确的，但不能因此拒绝用户明确要求的“已知金额最大值”。添加通用契约应在第二个结构不同的适配器证明，不给核心写芋道特例。
5. **减少无意义投票/修复。** 当前初始双解释已经并行。首测 36 道三调用题中位 10.393 秒，12 道六次以上调用题中位 36.489 秒。后续源码核对确认：执行器已尝试解析后比较，投票对普通事实保留整个 `Resolved`、纯页面只比较 URL，并非只按原始 JSON 分组。可研究不影响语义的可选页面/描述差异是否导致额外调用，再测规范化能否减少调用；不能合并条件不同但数值巧合相同的答案。直接取消第二解释的准确率收益未知。三调用与长链样本难度不同，相关性不能当作删除调用的因果收益。
6. **分别测供应商和产品阶段。** 三个非思考输入 cached 比例均约 77%，首模型请求字节中位均 7,614；Qwen 关推理的主要变化是输出下降，调用仅从 132 到 130。说明继续压 prompt 并非唯一瓶颈。业务解释与源码定位/回答可在依赖满足后研究并行；有依赖的观察、页面操作和审批不能并行争用。

历史 v6 当前组合为 57/63、中位 23.266 秒、P95 35.412 秒，旧 A 为 59/63、中位 18.785 秒。它们是已见过题集、真实 Chromium 装置；v7 新题、不同合成目录、transport double，**不能拿 16.97 与 23.27 直接宣布本次产品变快**。此次产品根本没有改变。已修复 22/63 的回退，不等于泛化、能力覆盖和用户体验已经达标。
