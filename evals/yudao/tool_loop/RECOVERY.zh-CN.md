# 2026-10-01—02：准确率回退修复与有界源码问答

此前通用工具循环的完整原始判分只有 22/63，输入 426.7 万 tokens。这个回退是真实问题，不能用局部计数提速或审计引用投影替代整体验收。本次恢复分阶段业务声明与确定性解析，并保留不依赖 SourceMap 的原始源码问答。主结果使用最终冻结代码完整重跑，所有失败保留。

## 为什么会回退

1. 通用循环把实体发现、字段选择、条件、记录绑定、聚合和最终措辞交给多次串行模型决定。每一步携带越来越长的工具历史，既增加输入，也增加改变查询范围、丢失混合目标和错误完成声明的机会。相同业务读取在旧路径主要由确定性解析器完成。
2. 源码引用只留在内部，旧题要求正文有可核验引证，因此规则题全部失分。但此前的辅助引用投影仍只能得到 37/63，说明还有执行和范围问题，不能把回退全解释成输出格式。
3. 原始词项检索常命中接口、错误常量或调用者，缺少实际校验条件及被调用的校验函数。模型不能把错误文案当成完整规则。
4. 小模型的嵌套工具 JSON 出现转义和数组序列化故障；原样重试不能提供有用的修复信息。静态工程职责也容易被错误归为业务负责人或必须查询 Git。
5. 原有选择值最多保留 8 个，尾部状态被截断；页面键与页面筛选器说明不够明确。缺失金额的旧求和可能静默省略未知值，得到不完整合计。

这些是代码和本次失败记录支持的原因，不是关于所有模型、所有应用的性能定律。

## 实现

- 一次有界范围声明保留业务、源码和页面的全部交付目标，支持混合请求，不使用单一分类标签。业务继续使用既有成对解释、确定性记录/条件解析和当前账号的 API 读取；不重新建立浏览器执行平台。
- 原生芋道宿主使用 `GoalTurnExecutor(repository_answers=True)`；已有调用默认关闭新组合。可选源码能力未配置时，普通业务查询和导航仍然运行。源码能力不授予 API、页面或写入权限，核心没有芋道专用协议；Contacts REST 合成应用验证了同一组合。
- 原始仓库检索依然只读部署白名单。相邻行保持校验与错误文案在一起，精确文件/符号匹配和一次有界符号关联补充实际使用位置；同时保留原始词项命中。索引搜索使用启动快照，返回前核验本地发布字节。
- 源码阶段先用少量匹配摘要声明定向查询，或选择最小的已有主证据；再从有界片段中选服务端编号的原文支持。每项最多 3 个初始查询、12 个证据窗口、4 个支持；正文显示路径、行号、release 和 hash。定位与回答合计只允许一次格式修复，不累计通用工具历史。
- 平铺范围/回答字段避免嵌套转义；简单数组被包装成 JSON 字符串时只解码一次，仍检查数量、类型、引用范围与发布字节，不猜测修复坏 JSON。失败的定向查询不把原已验证的匹配当作消失。
- 工程维护团队可来自源码、CODEOWNERS 或文档；提交/修改历史才需要 Git。文档声明仅建立文档中的知识，不证明代码运行。静态阶段只负责该静态问题，业务部分另行读取。
- 完整保留选择值；明确页面键与筛选器的区别。缺失、布尔、非数值或非有限求和字段如实拒绝，合法数值零保留。
- 每次源码/业务工具结果回到同一服务端回合，下一决策前有新页面观察。浏览器端没有源码索引、业务规划、模型凭证或判分器。

源码原文校验只证明出处，不证明模型转述的语义蕴含，也不证明未命中内容不存在。Git 历史、未提供的 API 字段、未启用的写入和页签点击仍有明确限制。

## 评测方法

使用此前已见过的封存 `yudao-goals-zh-v6-holdout.json` 与原 rubric 7 判分器，未改题目、truth、regex 或引证判定。相同本地可重置合成数据库、普通读者账号、8 个模块和源码发布 `v2026.09`，每题新会话，参考时钟固定 2026-09-30。最终生产代码归档冻结后完整运行，没有挑选通过题或补写失败答案。

模型为 `.env` 的 `qwen3.8-flash`，provider `ws-ld6klhbp5exxks76`；`thinking_budget=1024`、`parallel_tool_calls=false` 保持不变，每套 2 条通道。63 题使用实际 Chromium；attempt 时间包括准备、执行和最终页面采样，共享源码索引在计时外。

40 题由实现 Agent 编写，覆盖源码职责/规则、计数、多条件、字段/关联值、金额及零值、完整求和、并列极值、列表、空结果、混合目标、页面、拒绝与注入边界。不是用户随口提出的 5 题，也不是独立留出集。浏览器使用既有产品传输替身，时间是服务端回合，不与 63 题直接横比。预期仅存在于评估器，不进入 Agent 上下文。

扩展回归发现替身标记 URL 就绪但没有报告列表已渲染；目标式执行器因此正确拒绝页面完成。仅给替身补上其实际模拟的 `active_view=list` 并测试连续观察，原题和判分不变。最终旧通用循环与新组合在同一修正装置上完整重跑。之前未修正装置的结果只作为历史，不能替代这次对照。

不同轮次存在供应商负载和输出随机波动，部分运行与本地检查或另一题集重叠。这是单轮观察，不能宣称性能因果已隔离、准确率普遍达到 90%，或线上 UI 已达标。

相较 D，输入减少 **83.7%**，请求减少 **36.6%**，登记费率计费减少约 **72.6%**；中位耗时下降 **15.3%**，平均下降 **32.1%**，P95 下降 **63.0%**。相较旧 A，中位和平均仍更慢，不能宣称已经超过重构前的速度。

最终 63 题的 provider cached 输入为 399,616/695,595（57.4%），D 为 2,981,376/4,266,926（69.9%）。本次并没有提高 provider 缓存比例；收益主要来自减少总输入。业务声明的已有账号/模型/版本/上下文绑定缓存保留，业务数据仍重新按当前账号读取。
